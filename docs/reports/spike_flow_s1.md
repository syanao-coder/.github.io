## 1. 結論（1.1.0）

- 🔴 **犯人は自前の JS ではない。** 自前の処理（流しの描画・tick・メーター・埋め込みの受信）は **32〜39 ms/秒**、落ちたフレームで失った時間は **299〜423 ms/秒**（10倍以上）。
- 🔴 **YouTube の枠は別プロセス**（`about:processes` で youtube.com が別の行 ─ 利用者 T1）。YouTube の JS が同じスレッドを使っているのでもない。
- 🔴 **ページの描画そのものが遅い。** フレーム間隔の**中央値が 38〜59ms**（毎秒 13〜20回。本来 16.7ms）。ときどき詰まるのではなく、常に遅い。→ 描画（画面の組み立て・合成）が重い（解釈）。
- **ぼかし付きの縁取り（`text-shadow` 2px ぼかし×4）が重さの一因**: 縁取りなし（F2 / F4）で中央値 42 / 38ms、ありで 59 / 57ms。
- 合成器に任せる（F3）だけでは効かない（描画の回数が少ないと動きの細かさは増えない）。**F4（縁取りなし＋合成器）は利用者の目で「滑らか」**。
- 利用者: **縁取りなしは視認性に劣る。** → 1.2.0 で「ぼかし無しの縁取り」と「流しを隠した基準（F0）」を測る。
- 本番コードへの変更なし。

## 8. 結果（1.2.0・2026-10-23）

### 8-1. 結論

- 🔴 **この PC の Floorp はハードウェアアクセラレーションが切れている。** `about:support` の「合成」が `HW_COMPOSITING: user disabled ─ Disabled by layers.acceleration.disabled=true`。そのため `WEBRENDER: unavailable-no-hw-compositing` になり、**画面の組み立てをすべて CPU（Software WebRender）で行っている。** D3D11 系の「ブロックリストに掲載」は、この設定から連鎖したもの（失敗コード `..._NEED_HWCOMP` / `..._D3D11_DISABLED`）で、GPU が拒否されたわけではない。
- GPU は **GeForce GTX 1660 SUPER**（VRAM 6GB・ドライバー 32.0.16.1714 / 2026-09-17）で、使えれば4枠の合成は軽い部類（解釈）。
- 1.1.0 の「自前の JS は 35 ms/秒なのに描画が毎秒13〜20回」は、これで説明がつく（解釈）。CPU で描くと、ぼかし付きの影は文字ごとにぼかしの計算が要り、コメントが動くたびにやり直しになる。
- 目視（4枠・🔊を開いたまま）:

| モード | 目視 |
| :--- | :--- |
| F0 流しを隠す（メーターのバー） | **滑らか** |
| F1 今のまま | カクつく |
| F5 ぼかし無しの縁取り | 少しカクつく・**読みやすさは F1 と同等（「読みやすい」）** |
| F6 F5＋合成器 | 少しカクつく（利用者「カクつくというより fps が低い。改善はしている」） |
| F4 縁取りなし＋合成器 | 滑らか |

- 縁取りの重さの順は F1 ＞ F5 ＞ F4（なし）で、1.1.0 と矛盾しない。**F5 は読みやすさを保ったまま軽くなる**ので、ハードウェアアクセラレーションの有無にかかわらず採る価値がある（判断）。
- メーターだけ（F0）なら滑らか → メーターのカクつきは**流しの描画に巻き込まれていた**（解釈）。

### 8-2. 測れなかった値

- 🔴 **R1 の数値（計測コードの出力）が貼られていない**（用紙「未記入 1件（R1）」）。フレーム間隔・失った時間・F0 の描画回数は無い。目視だけで判断した。
- ハードウェアアクセラレーションを入れたときの値（次の測定で取る）。
- `layers.acceleration.disabled=true` を利用者が意図して入れたか（以前に何かの不具合を避けるためだった可能性）は未確認。

### 8-3. 次

1. 利用者にハードウェアアクセラレーションを入れてもらい（Floorp の設定 → 一般 → パフォーマンス、または `about:config` の `layers.acceleration.disabled` を `false`）、再起動して**同じ用紙をもう一度**測る（`about:support` の「合成」が `WebRender`（Software でない）になったことも写す）。
2. 結果しだいで、ツール側のパッチ（縁取りをぼかし無しへ・メーターのバーを `transform: scaleX` へ・F6 が効けば流しを合成器へ）を決める。F5 はアクセラレーションの結果によらず入れる方向。
3. アクセラレーションを入れられない事情があるなら、ツール側の軽量化（上の3つ）だけで行く。
