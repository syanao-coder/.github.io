# スパイク A1 記録 ─ 枠ごとの音のレベルを測れるか

測定: 2026-10-21（利用者・Floorp・UA `Firefox/158.0`・Windows）
指示書: `docs/instructions/spike_audio_a1.md` / 計測コード `audio-a1-1.0.0` / 用紙 `tests/test_spike_audio_a1.html`

## 1. 結論

- **A2（`createMediaElementSource` で付け替え）は使える。** 音は聞こえ続け、レベルが取れ、**音量を掛けた後の音**（実際に鳴っている大きさ）を測れる。
- **A1（`mozCaptureStream` で写し取り）は使えない。** 計測の後、**その枠の音が戻らなかった**（Firefox で写し取ると元の音が止まる挙動）。
- 変更ファイル: なし（本番コードへの変更なし）。プロトコル変更なし。
- 測定環境: Floorp（UA `Firefox/158.0`）・1枠・`csCxiQIJ6TM`（話し続ける動画）・プレイヤー音量 60。

## 2. 実測

| 項目 | A1 写し取り（`D-Q1`） | A2 付け替え（`D-Q2`） |
| :--- | :--- | :--- |
| 判定 | 合格 4/4（PC 3/3） | 合格 4/4（PC 3/3） |
| 再生中の平均 / 最大 | -29.4 / -24.7 dB（声の帯域 -35.8） | -32.4 / -28.4 dB（声の帯域 -38.7） |
| 音量を半分にしたときの差 | -1.8 dB | **-5.4 dB**（≒ -6 dB ＝ 音量を掛けた後） |
| 一時停止 | 無音 0%（計測が音に反応している） | 無音 0% |
| `AudioContext` | `suspended` → `running`（パネルのボタンで `resume`） | 同じ |
| `getVolume` / `video.volume` / 比 | 60 / 0.6 / 1（この動画では YouTube の音量の均しなし） | 同じ |
| 🔴 利用者の耳 | **測り終えても音が戻らない** | **聞こえ続けた**（半分で小さく・停止で無音・その後戻った） |

- 実行順は A1 → A2。A1 のあと止まった音は、A2 で通り道を Web Audio 経由で出力へ繋いだことで戻ったと考えられる（解釈）。

## 3. 測れなかった値

- A1 で音が「測り始めから」消えたのか「測っている途中から」消えたのかは区別できない（用紙の選択肢が「測り終えても戻らない」）。どちらでも不採用は変わらない。
- A1 の「音量を半分で -1.8 dB」は、掛ける前（0 dB）とも後（-6 dB）とも言い切れない。4秒ごとに話の中身が変わるので ±2 dB 程度の揺れはありうる。A1 は不採用なので詰めない。
- `AudioContext` が**操作なしで** `running` になるかは測れていない。今回はパネルのボタン（埋め込みの中の操作）で `resume` した。Firefox は作った直後に `suspended` を返し、すぐ `running` へ移ることもあるので、`suspended` だけでは「操作が要る」と言えない。
- A2 で足される音の遅れ（Web Audio を通す分）は測っていない。全枠に同じ仕掛けを付ければ枠どうしの差は出ないはずだが、未確認。
- 複数枠を同時に測ったときの負荷は測っていない。
- 本番は content script（隔離された環境）から動かす。今回はコンソール（ページの環境）。隔離環境から `createMediaElementSource` が使えるかは未確認。

## 4. 指示書との差異・手戻り

- 指示書 2節 #4 のリスク（写し取りで元の音が止まる）が **A1 で実際に起きた**。A2 は `AudioContext` を `resume` で `running` にしてから付け替えたので無音にならなかった。
- 🔴 本番の設計への要件: **`AudioContext` が `running` になったのを確かめてから付け替える。** `suspended` のまま付け替えると、その枠が無音になるおそれがある（付け替えは元に戻せない）。

## 5. 管理側の誤り

- 用紙の選択肢で「測り始めから消えた」と「測り終えても戻らない」を分けたが、「途中で消えて戻らない」を想定しておらず、A1 の消えた時点を区別できなかった（3節）。結論は変わらない。
