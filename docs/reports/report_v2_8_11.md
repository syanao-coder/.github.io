## 2. 入ったもの

- 境界線のつまみ（`#gridSplitterLayer` / `.grid-splitter`）。比は構成の署名（`列x行[:pin]` / `n2:2x1` / `n2:1x2[:pin]`）ごとに `sync_grid_ratios` へ fr で保存。最小 80px。ピン枠の上にはつまみを出さない。ドラッグ中は iframe の `pointer-events` を切る。
- ダブルクリック（自前判定 450ms・4px）と上部の ⊞（比を変えた構成のときだけ表示）で均等に戻す。
- ローカル動画の履歴を押すと、その枠の file input を同期的に `click()`（`openLocalPicker`）。
- `setGridRatiosSuspended()`: D-Y / D-Z の間だけ保存した比を無視する（`runOne` が呼ぶ）。

## 3. 起きたことと原因

| # | 事象 | 原因 | 分類 |
| :-: | :--- | :--- | :--- |
| 1 | 実機でダブルクリックが効かない | 1回目の mouseup でつまみを作り直し、ネイティブの `dblclick`（2回とも同じ要素が条件）が発火しなかった | 本体の不具合。🔴 D-S1 がつまみへ直接 `dblclick` を合成していて**実機の発火条件を通っていなかった** ─ 管理側の誤り |
| 2 | 1回目の目視で「再読み込みで均等に戻った」 | **再現せず・原因不明**。再測1の目視と D-S2（実機で再読み込みをまたぐ）では保存値・メモリ上の値・列幅とも一致 | 未確定。再発したら D-S2 の観測（保存値 / メモリ / 署名 / 枠数 / style）で絞る |
| 3 | D-S2 が実機で判定不能 | 基準の列幅を `resetGridRatios()` の**前**に読んだ。利用者の保存値があると基準が均等でない。headless は保存値が空で通った | 基盤側の誤り（管理側） |

## 4. 測れなかった値

| # | 値 | 理由 |
| :-: | :--- | :--- |
| 1 | 1回目の「再読み込みで戻った」の原因 | 以後再現しない |
| 2 | 履歴から開いた選択画面で、実際にファイルを選んで再生できるか | 再測2で利用者の目視を求めなかった（D-Z2 は選択画面の直前で止める）。選んだ後は既存の `handleLocalSelect` 経路 |
| 3 | 9枠・ピンあり構成での手触り | 自動は 4枠 / 6枠 / ピン（4枠）だけ |

## 5. 規約・罠の新設（④で仕様書へ載せる候補・上限4件）

1. 🔴 **合成イベントは実機の発火条件を満たす形で送る。** ネイティブの `dblclick` は「2回とも同じ要素」でしか発火しない。要素へ直接 `dblclick` を合成すると、作り直しによる不発を見逃す。座標から `elementFromPoint` で毎回当て先を取る（`realDblClick`）。
2. 🔴 **基準値は前処理（リセット）の後に読む。** headless は保存値が空なので、前処理の前後で値が変わらず誤りが隠れる。PC に「基準が想定どおり（均等など）」を入れる。
3. 再読み込みをまたぐテストは `LS_RESUME` の `which` で振り分ける（D-M7 / D-S2）。
