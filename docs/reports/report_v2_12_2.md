# v2.12.2 記録 ─ ライブのチャットの塊の平滑化（🔴 不具合 → v2.12.3）

測定: 2026-10-24（利用者・Floorp・UA `Firefox/158.0`・画面 1129×939）
指示書: `docs/instructions/instr_v2_12_2.md` / 用紙: `tests/test_v2_12_2.html`（v2.12.3 で `test_v2_12_3.html` へ）
素材: ライブ `i9B_4CRTidM`

## 1. 結論

- 🔴 **不合格（実質）。ページを開いた時点より後のライブのコメントが、チャット欄にも流しにも一切出なかった**（利用者 FREE「全体とか上位とかを切り替えた直後は表示分は流れるけど、以降コメントはチャット欄も画面上も一切流れませんでした」）。
- 原因（管理側の誤り）: `liveSmoothIngest` が `now − t`（`performance.now()` − 配信開始からの経過）を「遅れ」として扱った。**2つは起点が違い、差には任意の定数が乗る**（配信開始の後にページを開くと大きな負）。負の値を `K = max(…, 0)` で 0 に丸め、出す時刻 `t + 0` が数時間先になった。→ v2.12.3 で「いちばん小さい差を基準にした相対の遅れ」に直し、出す時刻を「届いてから30秒以内」に抑える保険を足した。
- R1（すべて実行 23本）合格。`D-A5` 16/16・`D-A6` 3/3 合格（**どちらも偽のデータで、上の取り違えを再現していなかった**）。`D-W4` は判定不能（後半のチャンク 2回で PC 不成立）だが、観測は**後半の表示 0件・K 0ms**で、不具合そのものを示していた。
- 縁取り（`D-A6`）は実機の計算後の値でぼかし無し（`1px 1px 0px` ×4）を確認。目視（R3e）は流れなかったので未評価。
- v2.11.1 の持ち越し（R6・R7）は未実施。

## 4. 指示書との差異・手戻り

- 指示書 3-1節に「同じ時計どうしの差なので PC の時計のずれは効かない」と書いた。**誤り**（同じ時計ではない。速さが同じだけで起点が違う）。
- `D-W4` の PC「後半にチャンク3回以上」がこのライブの間隔（10〜15秒）では満たせなかった。→ v1.22.1 で「2回以上・合わせて6件以上」に緩め、**「後半に届いた分が15秒待つまでに8割以上出た」を判定に足した**（v2.12.2 ならここで不合格になる）。

## 5. 管理側の誤り

- 🔴 **偽のデータを実装と同じ前提で作った。** `D-A5` と headless の検証台は、コメントの時刻 `t` を `performance.now()` 基準で作っていた＝実装の誤った前提（同じ起点）をテストのデータが共有していたので、どの判定も通った。実機の `t` は配信開始からの経過。→ v1.22.1 の `D-A5` は起点のずれ（+2時間・−1.4時間）で同じ結果になることを見る。v2.12.2 の `index.html` に当てると不合格（+2時間で「3 / 3 / 3」＝新しいコメントが出ない）を再現した。
- 実機で壊れたまま Pages に出した（v2.12.2 は利用者指示どおりマージ済み）。v2.13.0 より先に v2.12.3 を出す。

## 6. 規約の新設（候補・④で利用者に確認）

- 鉄則候補: **偽のデータは実機の値の起点・単位で作る。** 実装が前提にしている関係（同じ時計・同じ単位）をテストのデータが黙って満たしていないかを確かめる。
