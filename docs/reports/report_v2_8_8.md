## 3. `D-Y13` の不合格への対処

| 項目 | 内容 |
| :--- | :--- |
| 原因 | 秒送りを文字（`⏪10s`）にしたぶん、ボタンの合計幅が狭い枠のヘッダー幅を超えた。headless Chromium（画面幅1424・ヘッダー465px）では収まっていたが、**Floorp は絵文字の字幅が大きく（アイコン 36 → 40px）、画面幅も狭かった（1309px → ヘッダー426px）** |
| 対処 | 秒数を `<span class="skip-sec">` に分け、**ヘッダーの幅が 500px 以下のときは CSS のコンテナクエリで秒数を隠して記号だけにする**（秒数はホバーの title で読める）。`.player-header` に `container-type: inline-size` を付けた |
| しきい値 500px の根拠 | Floorp の実測（ボタン合計381px＋余白など76px＝457px）で秒数ありが収まる最小幅は約457px。余裕を見て500px |
| 確認（headless Chromium / 1309×939） | `D-Y13` 3/3・`D-U2` 9/9・`D-Y7` 4/4。9枠のヘッダーは右端に 10px の余裕 |
| 判定は変えていない | `D-Y13` / `D-U2` は修正前と同じコードで測る（`textContent` は隠しても変わらないので `D-U2` の期待値はそのまま） |

⚠️ **版数は 2.8.8 のまま**（未確定の版の中での修正）。再測用紙は `tests/test_v2_8_8_retest.html`。

## 5. 利用者の新しい要望（2026-10-02 / ロードマップ未反映）

| # | 要望 | 所見（実コードを読んだ範囲） |
| :-: | :--- | :--- |
| 1 | **枠の境界線をドラッグして、格子の範囲で枠の大きさを自由に変えたい** | `.players-grid` の列・行は均等割り（`1fr`）。境界にドラッグ用のつまみを置き、列幅・行高を `fr` の比で持てば作れる。⚠️ ピン留め（2×2）・自動列数・枠数の変更と組み合わさるので、**比率をいつ捨てるか（枠数や列数が変わったとき）**を決める必要がある。A側のみ＝パッチ |
| 2 | **各枠（特にローカル動画）の上下左右をカットする機能**。ウルトラワイドの黒帯で本体が小さくなるため。**操作部分はカットしない**。「横幅または縦幅を固定した拡大」でもよい | **ローカル動画は実現できる。** 動画（`<video>`）と操作バー（`localOverlay_*`）が別の要素なので、動画だけを拡大して枠で切り取れば操作バーは残る。⚠️ **YouTube の枠は、動画と YouTube 自身の操作バーが1つの iframe の中にあるため、動画だけを拡大することはできない**（拡大すると YouTube の操作バーも一緒に切れる）。YouTube の枠でもやる場合は「操作はヘッダーと一括コントローラーで行い、YouTube の操作バーは切れてよい」という割り切りが要る。A側のみ＝パッチ |
