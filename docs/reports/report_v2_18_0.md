## 1. 結論

- **機能は合格。保存に不具合あり → v2.18.1 で直す。** 自動の測定はすべて合格。耳での聞き比べも良好。ただし R4d で**読み直したら設定が消えていた**。
- 🔴 **枠の中で効いた**（`D-W10`・0.2秒・抑えた量の最大 28.3 dB・遅れ 6ms ─ Chromium の headless と同じ 6ms。Floorp の `DynamicsCompressorNode` も同じ作りと見てよい）。
- 耳（R4）: キツい高音は「**和らいだ**」・抑えていない部分の音色は「**少し変わる**」。気に入った設定は利用者の記入で「4khz、32db、8:1」（＝ 4kHz・-32 dB・8:1 と読む）。
- 🔴 **R4d「消えていた」の原因**: 設定を**枠 ID**（`card_N`）で保存していた。枠 ID は再読み込みのたびに `card_1` から振り直されるが、枠の削除・マイリストの読み込みのあとは並び順とずれる。R3 の2回目は `card_4`（1番目の枠）で測っていた ＝ ずれていた。読み直すと1番目の枠は `card_1` になり、`card_4` の値は当てる枠が無く捨てられた。🔴 **枠ごとの音量（v2.8.9 の `sync_card_volume`）も同じ不具合を持っていた**（headless で再現: 3枠で先頭を消して足す → 先頭の枠の値が読み直しで2番目へ移る）。
- FREE: デバッグパネルの整頓の要望 → v2.18.1 に同梱。
- 変更ファイル: `index.html`・`debug_suite.js`（v1.28.0）・`addon/content_yt_embed.js`＋`manifest.json`（2.16.0・`v2.16.0.zip`）・用紙。マイナー（`SYNC_EMBED_COMP`・`SYNC_EMBED_LEVEL` に `compOn` / `compDb` / `compLatencyMs`）。

## 4. 指示書との差異・手戻り

- 実装中に3つ直した（指示書 6節）: lowpass / highpass の Q は dB・コンプレッサーの遅れを低い側でそろえる・自動の持ち上げを打ち消す。
- 🔴 保存の不具合は headless の判定（`D-A8`）が**同じ枠 ID のまま**保存を読んでいたので見逃した。再読み込みと ID のずれを組み合わせた判定が無かった → v2.18.1 の `D-A9`。

## 5. 管理側の誤り

- 🔴 **枠ごとの値を枠 ID で保存する作りを、v2.8.9 の音量からそのまま写した。** v2.8.9 のコメントに「枠IDは作り直すたびに新しい番号になる」と書いてありながら、読み直しで ID と並び順がずれる場合を考えていなかった。保存URLは並び順の番号（`sync_url_<番号>`）なのに、設定だけ ID だった（`get-protocol-spec` 11節 持ち越し6 と同じ根）。

## 6. 規約の新設（④で利用者に確認）

- 案: **枠ごとに保存する値は、並び順の番号で保存する**（保存URLと同じ）。判定は「ID と並び順をずらしてから再読み込み」で確かめる（`D-A9` の形）。
