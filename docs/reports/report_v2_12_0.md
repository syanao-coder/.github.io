## 1. 結論

- **合格。** R1（すべて実行 23本）・R2（🎯 5本: `D-V1` / `D-V2` / `D-A1` / `D-A4` 15/15 / `D-W3` 4/4）すべて合格。判定不能 0。
- 🔴 **アドオン（content script・隔離された環境）から `createMediaElementSource` が動いた**（スパイク A1 はページの環境だったので、ここが最大の未確認点だった）。2枠とも `running`、一時停止で無音、再開で音が戻る。
- 目視: スライダーを下げるとその枠のバーと数値が下がる・**音は途切れなかった**・**枠どうしの音のずれは前と変わらない**。
- 🔴 利用者の評価は「**動くが比べにくい**」。4枠以上では「**バーの動きの滑らかさが減る**」。要望: **ピークホールド**（終端に線を残し、超える音が来るまでゆっくり左へ落ちる）。→ v2.12.1（パッチ・A側だけ）で対応。
- 変更ファイル: `index.html` / `debug_suite.js` / `addon/content_yt_embed.js` / `addon/manifest.json` / `v2.12.0.zip`。プロトコル変更あり（`SYNC_EMBED_METER` / `SYNC_EMBED_LEVEL` / `SYNC_EMBED_METER_BROKEN`）。
- v2.11.1 のライブの持ち越し（R6・R7）は未実施（ライブなし）。

## 3. 測れなかった値

- 重さ（R5）: 利用者が「測れなかった」。数値（CPU）は無い。観察は「4枠以上でバーの動きの滑らかさが減る」だけ。
- 9枠での動作・負荷は未測定。
- BROKEN（付け替え後に音の処理が止まる）は実機で起きていない。読み直しの経路は headless だけで確認。
- 「比べにくい」の具体的な理由は聞けていない（数値が瞬間値で暴れる・バーが細かく揺れる、のどれか）。ピークホールドと動きのなめらか化で改善するかを v2.12.1 で見る。
