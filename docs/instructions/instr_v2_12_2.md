## 3. 設計（平滑化）

### 3-1. 考え方

- 届いた時刻 `A`（`performance.now()`）と投稿の時刻 `t` の差 `A − t` を「遅れの標本」とする（同じ時計どうしの差なので、PC の時計のずれは効かない）。
- 1つのチャンクの中で一番古いコメントの標本が最大（≒ 取得間隔＋サーバーの遅れ）。
- **遅れ `K` = 標本の最大**（チャンクごとに更新）。各コメントの出す時刻は **`due = t + K`**。一番古いコメントは届いた瞬間、一番新しいコメントは約 `K` 後に出る。→ 投稿の間隔のまま出る。

### 3-2. 定数と規則

| 定数 | 値 | 意味 |
| :--- | :-- | :--- |
| `LIVE_SMOOTH_FEATURE` | `true` | 🔴 **逃げ道。** `false` で従来どおり（届いたら全部出す） |
| `LIVE_SMOOTH_MAX_LAG_MS` | 30000 | これを超える標本は**すぐ出し、`K` に入れない**（初回の過去ぶん・復帰後の重複などで `K` が暴れないように） |
| `LIVE_SMOOTH_DECAY` | 0.1 | `K` は前のチャンクから経った時間 × 0.1 だけ縮む（1回だけ遅かった取得のあと、少しずつ戻す。急に縮めると塊が出る） |

- 🔴 **最初にコメントの入ったチャンク（過去ぶん）は全部すぐ出す。** `K` は2つ目のチャンクから見積もる。
- `K = max(前の K − 経過 × DECAY, このチャンクの標本の最大)`。標本の最大は `MAX_LAG` 以下のものだけ。
- `due[i] = max(t[i] + K, due[i−1])`（順番を崩さない）。`MAX_LAG` を超えたもの・初回は `due = A`（ただし前の `due` より前にはしない）。
- 予定表は `store.liveDue[]`（`comments` と同じ添字）・出した数 `store.liveShown`・遅れ `store.liveLagMs`。
- `liveShownCount(store, now)`: `liveShown` を `due ≤ now` まで進めて返す。🔴 **`liveDue` と `comments` の長さが違えば（予定表の無いコメントがある）`comments.length` を返す**（取りこぼすより出す側に倒す）。逃げ道が `false` のときも `comments.length`。
- チャット欄・組み直し・流しは、**`comments.length` の代わりに `liveShownCount` まで**を使う。流しの開いた時点の起点・溜まり（60件）も `liveShownCount` 基準。
- 遅れは「約 N 秒遅れ」を見出しの `title` にだけ出す（見た目は変えない）。

### 3-3. 代償（利用者に説明済み）

塊の中で一番新しいコメントは、今より最大で1回分の取得間隔（約10秒）遅れて出る。

## 5. 判定（`debug_suite.js` v1.22.0）

| ID | 内容 | PC |
| :--- | :--- | :--- |
| `D-A5` | A側だけ。偽のライブの取得（`handleChatMeta` / `handleChatChunk`）へ、初回（過去ぶん）と2回目のチャンクを流す。`liveSmoothIngest` へ時刻を渡して: 初回は全部すぐ／2回目は `K` ≒ 一番古い標本・出す数が時刻とともに増える（届いた瞬間は1件、`K` 後に全部）／`MAX_LAG` 超えはすぐ出し `K` を変えない／`due` が単調／`K` の縮み。**チャット欄の行数**が予定どおり増える（本物の `pumpChatProgress`）。逃げ道 `false` で届いた瞬間に全部 | 🔴 逃げ道を切ると届いた瞬間に全部出る（測り方が差を拾える証拠）・偽の枠のチャット欄がある |
| `D-A6` | 流しの縁取り。偽のコメントを1件生成し、計算後の `text-shadow` に**ぼかし（3つ目の長さ）が 0 以外のものが無い**・影が4つ。設定「縁取り」オフで `none` | 生成したコメントの `text-shadow` を読める |
| `D-W4` | 実機（ライブ）。チャット欄を開いたライブ枠で、前半30秒は逃げ道を切り（従来）、後半30秒は平滑化して、チャット欄へ**行が足された時刻**を数える（MutationObserver）。指標: 「チャンクが届いてから1秒以内に出た割合」 | 🔴 前半（従来）でその割合が 80% 以上（塊で届いている証拠）・チャンクが3回以上届き、うち2回以上が3件以上 |

- `D-W4` の合格: 後半の割合が **50% 以下**、遅れ `K` が `MAX_LAG` 未満。観測: 前後半の「1秒あたりの最大件数」、`K`。
- `VERSION_FOCUS` = `D-V1` → `D-V2` → `D-A5` → `D-A6` → `D-W4`。`D-W4` 以外は「すべて実行」でも回る。
- 🔴 割合のしきい値の根拠: 塊が `K` 秒に散ると、1秒以内に出るのは `1/K` 程度（`K` = 10秒なら 10%）。50% は `K` が2秒を下回る（平滑化がほぼ効いていない）ときだけ不合格にする幅。
