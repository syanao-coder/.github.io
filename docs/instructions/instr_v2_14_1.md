## 1. やること（利用者要望 2026-10-25）

「いちいちクライアント ID を貼らずに、アカウントのログインだけで同期できないか」。→ 利用者の作ったクライアント ID をコードに埋め込む。

- 🔴 クライアント ID は秘密の値ではない（ログインのたびに Google へ送られ、ページからも見える）。使えるのは OAuth 同意画面のテストユーザーだけで、ドライブはそれぞれ自分の `appDataFolder` しか触れない。秘密の値（クライアント シークレット）は使わない。
- v2.14.0 で貼り付け式にした理由（ID を作り直しても配り直しが要らない）は、Pages へ出すだけで全環境に届くので小さい。逃げ道として上書きの欄は残す。

## 2. 着手前に実コードで確かめたこと

| # | 確認 | 結果 |
| :-: | :--- | :--- |
| 1 | ID の読み口 | `gdriveClientId()` 1か所（`gdriveEnsureToken` / `gdriveSync` / `gdriveLogin` / `gdrivePreload` がここを通る） |
| 2 | 貼り付け欄 | `#gdriveClientId`（`onchange` → `setGdriveClientId`）。状態の行は ID が無いと「未設定」 |
| 3 | 先読み | `initApp` で ID があれば GIS を先に読む → 埋め込むと全員が毎回読むことになる |

## 3. 設計

- `GDRIVE_CLIENT_ID_BUILTIN`（利用者の ID）。`gdriveClientId()` は `sync_gdrive_client` に値があればそれ、無ければ既定。
- 欄は `<details id="gdriveDetails">`「詳細（クライアント ID の上書き）」の中へ。欄には上書きの値だけを出す（空欄＝既定）。空にすると `sync_gdrive_client` を消す。ID を変えたらトークンを捨てる。
- 状態の行の初期値「☁ を押すと同期を始めます」（「未設定」は出さない）。
- 先読み: 起動時は「同期を使う」環境だけ。初回は 📂 を開いたとき（`gdriveInitUI`）に読む（クリックから窓までの遅れ対策は保つ）。
- 版数: `APP_VERSION` 2.14.1・`APP_HISTORY` 50件・`debug_suite.js` v1.24.1（`D-N3` 50）。
