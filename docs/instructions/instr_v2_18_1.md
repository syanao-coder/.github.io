## 1. やること

### 1-1. v2.18.0 の R4d「消えていた」

- 🔴 再現（headless）: 3枠 → 先頭の枠を ✕ で消して1枠足す（枠 ID は `card_2 / card_3 / card_4`）→ 先頭の枠に高音を抑える（オン）と音量 37 → 再読み込み → 枠 ID は `card_1 / card_2 / card_3` に振り直され、**設定は2番目の枠へ移った**（先頭の枠は既定に戻った）。
- 原因: `sync_card_comp`（v2.18.0）と `sync_card_volume`（v2.8.9）は**枠 ID で保存**している。枠 ID は再読み込みのたびに `card_1` から振り直されるが、枠の削除・マイリストの読み込み（保存したときの ID で作り直す）のあとは**並び順とずれる**。保存URLの復元は並び順の番号（`sync_url_<番号>`）なので、動画は元の枠へ戻るのに設定だけが別の枠へ移る／捨てられる。R3 で `card_4` を使っていたので、測定のときもずれていた。
- 🔴 音量（v2.8.9）も同じ不具合を持っていた（v2.8.9 からある・気づかなかった）。同じ作りなので一緒に直す。

### 1-2. 利用者の要望（v2.18.0 の FREE）

「テストに使うものは個別に実行の外に出し、使わないものは個別に実行内に格納。個別に実行の中身のボタンが番号順に並んでおらず探しにくい。整頓してください」

## 3. 設計

### 3-1. A側（v2.18.1）

- 保存の形を**並び順の番号（1..N）**に変える（`sync_url_<番号>` と揃える）。メモリ上は今までどおり枠 ID で持つ。
  - `saveSlotMap(key, map)`: `getSortedCards` の i 番目の枠の値を `"i+1"` に書く。
  - `readSlotMap(key)`: 今の並びの i 番目の枠に `"i+1"` の値を当てる。v2.18.0 までの形（`card_N`）は、同じ ID の枠があればその値を使う（再読み込みの直後は `card_N` が N 番目なので、ずれていなかった人の値は残る）。
- 読み込み（枠ができてから）: `initializeGrid` の**初回**と `loadSession` のあとに `loadCardVolumes()` / `loadCardComps()`。
- 保存: 値を変えたとき（従来）＋ `resaveUrlsBasedOnOrder`（並べ替え・削除・空にする・動画の読み込み）＋ `initializeGrid` の終わり（枠数の変更 ─ 減らした枠の値を消す）。
  - 🔴 `initializeGrid` の初回は**読んでから保存する**（逆だと空のメモリで保存を消す）。
- 版数: `APP_VERSION` 2.18.1・`ADDON_REQUIRED_VERSION` 2.16.0（据え置き）・`APP_HISTORY` 56件。
