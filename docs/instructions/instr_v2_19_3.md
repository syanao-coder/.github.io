読む仕様書: `get-dev-workflow` / `get-debug-suite`（9-B-21節）/ `get-ui-spec` 16節

## 1. やること

v2.19.2 の R3c で利用者が「強いて言えば枠の縦の大きさの 1/4 くらい（1〜2枠でブラウザの縦いっぱいのときはその限りではない）」と答えた。2026-11-04 に「自動を足して」と指示があった。

| 項目 | 決めたこと（よしなに） |
| :--- | :--- |
| 自動の幅 | **枠（`.player-card`）の高さ ÷ 4** を四捨五入し、100〜240px に収める。1〜2枠で縦いっぱいの枠は 240px で止まる（「その限りではない」への答え） |
| 枠ごと | 枠ごとに自分の高さで決める。枠の高さが変わったら（枠数・列数・境界線のドラッグ・ウィンドウ）タイルを付け直す（`ResizeObserver`・作り直さずに寸法だけ書き換える） |
| 操作 | 見出しの右に「自動」「－」「＋」。🔴 **－ は今の幅より小さい段（100 / 140 / 180 / 240）へ、＋ は大きい段へ移り、手動になる**。どちらも、それより小さい段・大きい段が無ければ押せない。「自動」を押すと自動へ戻る（自動のときは明るく出す） |
| 保存 | `sync_hist_tile` に `auto`（自動）または `0`〜`3`（手動の段）。🔴 **既定は自動**（値が無いとき・読めない値のとき）。v2.19.2 で ＋／－ を押した人は手動のまま残る |
| 文字 | 幅に合わせて大きく（式は v2.19.2 と同じ・自動の幅でも同じ式） |

### 境界値（式に代入した結果）

| 枠の高さ | ÷4 | 幅 |
| :-: | :-: | :-: |
| 94px（薄い枠） | 23.5 | **100** |
| 400px | 100 | **100** |
| 560px | 140 | **140** |
| 722px | 180.5 | **181** |
| 960px | 240 | **240** |
| 1200px | 300 | **240** |

⚠️ タイルが大きくなって枠が伸び、また大きくなる（ぐるぐる）が起きないかを確かめる。枠の高さはグリッドで決まり、中身では伸びない作り（`min-height:0`・`overflow:hidden` ─ `get-ui-spec` 6節）だが、headless で枠の高さを変えて確かめる。

## 2. 判定

- `D-F1` を作り直す（中身の判定は v2.19.2 と同じ・手動の 140px で始める）。足すもの:
  - 読み取りの決まり（`parseHistTile`）: 値なし → 自動・`auto` → 自動・`2` → 手動 180・`9` → 自動。
  - 🔴 自動のとき、タイルの幅＝枠の高さ÷4（100〜240px に収める）。
  - 🔴 枠の高さを変えるとタイルの幅が付いてくる（560px → 140・800px → 200）。PC: 2つの高さで幅が違う値になる。
  - 収める: 300px → 100・1200px → 240。
  - 「自動」のボタンがあり、自動のときは明るい。
  - 自動（200px）から ＋ → 240 の手動・`sync_hist_tile` が `3`。－ → 180。
  - 「自動」で戻る・`sync_hist_tile` が `auto`。
  - 自動のときの － ／ ＋ の押せる・押せない（幅 100 で － が押せない／幅 240 で ＋ が押せない）。
- 後始末で枠の高さ・大きさの保存を戻す。
- `VERSION_FOCUS` = `D-V1` → `D-V2` → `D-F1` → `D-Z2`。版数 `APP_VERSION` 2.19.3・`APP_HISTORY` 60件・`debug_suite.js` v1.30.3。
