## 1. やること（2026-10-24 利用者選択）

v2.13.0 の R6 で、ライブの取得が開始約3分で止まり（心拍が途絶え、A側の見張りが `STALLED`）、利用者が 🔄 を押すまで戻らなかった。**原因によらず、A側がライブの取得を自動で取り直す**。

除外: 止まった原因の究明（持ち越し13のまま）。`D-L9` の判定の強化（利用者が今回は選ばなかった）。流しの同時表示数の既定（保留）。

## 2. 着手前に実コードで確かめたこと

| # | 確認 | 結果 |
| :-: | :--- | :--- |
| 1 | 途切れの入口 | `failChat(requestId, videoId, error)` に3経路: 見張りの発火（`armChatWatchdog`・取得中は心拍ごとに45秒で張り直し）／`meta` の `ok:false`／`done` の `ok:false`。ライブなら `endReason = 'STALLED'`、`chatState` は `ready` |
| 2 | 🔴 B側への中止 | `failChat` は `CHAT_STREAM_CANCEL` を**送らない**。見張りが発火しても B側のジョブは生きている可能性がある → 取り直す前に古い `requestId` へ中止を送る |
| 3 | 🔄 の実体 | `reloadChat` は `store` を捨てて取り直す（今までのコメントが消える）。自動の取り直しでは**捨てない** |
| 4 | `requestChatArchive` | `chatState` を `loading` にし、キャッシュを照会してから要求する。ライブはキャッシュしないので照会は不要。`loading` にするとチャット欄の追加（`pumpChatProgress`）が止まる → 自動の取り直しは専用の関数で送る |
| 5 | 🔴 重複 | 新しい取得の最初の応答は**直近の過去ぶん**で、手元のコメントと重なる。A側のコメントは `{t, n, m, p}` だけで id が無い（B側は id で重複を消しているがジョブごと）。`t` は同じ配信開始から作るので同じ値になる → `t + n + m` で重複を消す |
| 6 | 番号 | 新しい取得は `seq` が 0 から。`store.nextSeq` を 0 に戻す（`gap` の誤検出を避ける） |
| 7 | `RECOVERY_FAILED` | B側が5分ほど復帰を試みて諦めた終わり方（`done ok:true`）。これも取り直しの対象にする |
| 8 | 配信が終わっていた | 取り直した `meta` が `live:false` なら、B側はアーカイブとして取りにいく → すぐ中止し `ENDED` で終える（アーカイブを混ぜない） |
| 9 | 枠を閉じた | 待っている間に `store` が消えた（`releaseUnusedChatData`）・どの枠も参照していない（`collectChatRefs`）なら取り直さない |

## 3. 設計

| 定数 | 値 | 意味 |
| :--- | :-- | :--- |
| `LIVE_AUTO_RETRY_MAX` | 3 | 続けて取り直す上限。🔴 逃げ道: 0 で従来どおり（`liveAutoRetryMax` で試験から変えられる） |
| `LIVE_AUTO_RETRY_DELAY_MS` | 3000 | 取り直すまでの待ち（`liveAutoRetryDelayMs`） |

- `failChat` の先頭と `done`（`RECOVERY_FAILED`）で、`store.live` かつ `endReason` が正常な終わり（`ENDED`）でなく、続けての回数が上限未満なら `scheduleLiveRetry(videoId, 古いrequestId, 理由)`。
  - 古い `requestId` へ `CHAT_STREAM_CANCEL`・見張りを外す。`chatState` は `streaming` のまま（チャット欄の追加と流しを止めない）。`store.livePhase = 'recover'`（見出しは「🔴 再接続中」）。
  - 待ちのあと `startLiveRetry`: 新しい `requestId` で `CHAT_STREAM_REQUEST`（キャッシュ照会なし）・`CHAT_META_TIMEOUT_MS` の見張り。`store.retryRid`・`store.retryKeys`（直近500件の `t|n|m`）・`store.nextSeq = 0`。
- `meta`（取り直しの `requestId`）: `live !== true` なら中止して `endReason = 'ENDED'`・`ready`。
- `chunk`（取り直しの `requestId`）: `retryKeys` にあるコメントを捨ててから足す。足せたら（または心拍が来たら）続けての回数を 0 に戻す。
- 見出し: 取り直した回数（通算）を「・再接続N回」で出す。
- 上限に達したら従来どおり `STALLED`（「⚠途切れました・🔄で再取得」）。
- 版数: `APP_VERSION` 2.13.1・`APP_HISTORY` 47件・`debug_suite.js` v1.23.1（`D-N3` 47）。
