## 2. 着手前に実コードで確かめたこと（前提との食い違い）

| # | 前提（11節・CLAUDE.md） | 実コード | 対応 |
| :-: | :--- | :--- | :--- |
| 1 | 🔴 「アイコンを大きくするとヘッダーが高くなり薄い枠の可視領域が減る」 | **誤り。** `.player-header` のホバー時の高さは `var(--header-height)`（`30px × --ui-scale` ＝ 中で 37.5px）の**固定値**で、中身のボタンの高さでは伸びない（`overflow: hidden`）。v2.8.7 の `line-height: 0.77` は**ヘッダー高ではなくボタン自身の高さ**を保っていた | ヘッダー高の心配は不要。代わりに**ボタンがヘッダーからはみ出して切れないこと**を判定する（`D-Y13`）。⚠️ ただし横幅は増える。9枠・1424px幅で右端の ◀▶ が 22px はみ出したので、左右の padding を 0.4倍に詰め、秒送りの文字は元の大きさにした（headless Chromium で実測） |
| 2 | 「⤢ は 1.3倍でまだ小さい」 | 他のボタンはすべて 1.0倍。⤢ だけが 1.3倍 | **全ボタンを 1.5倍**にそろえ、`line-height` を 1/1.5 にしてボタンの箱の高さを据え置く |
| 3 | 🔒（常時表示）と新設定の関係 | 🔒 は `isControllerLocked`。`hideController()` が早期 return する | 🔒 は「常時表示」のまま独立に残す（3状態に統合しない）。**`D-Y8` が `toggleControllerLock()` を使っているので壊さないため** |
| 4 | 「`installCheck()` / `D-N5` は色を見ているだけ」 | そのとおり（`warn` / `ng` クラスの有無だけ） | 変更不要 |
| 5 | 既存の「全体のUIサイズ（小・中・大）」設定 | ヘッダーとボタンをまとめて拡大できる設定が既にある | R-4a は「ヘッダーの高さを変えずにアイコンだけ大きく」という別の要望として実装する。設定の存在は報告書で利用者に伝える |
