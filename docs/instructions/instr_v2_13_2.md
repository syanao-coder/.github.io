## 1. 不具合（利用者 2026-10-24・v2.13.0 の実機）

ライブの取得が止まった（`STALLED`）枠で 🔄 を押すと、**チャット欄は流れるがコメント流しは流れない**。流しをオンオフしても変わらない。

## 2. 原因（実コード・headless で再現）

- 🔄（`reloadChat`）は `chatStore[videoId]` を消して作り直す。
- 流しの `flowCursor[cardId]`（次に流す添字）は前の store の添字のまま残る（例: 2,942）。`pumpFlowProgress` は `flowVideoId` が変わったときだけ引き直すので、同じ動画の作り直しでは引き直さない。→ 新しい store がそこまで伸びるまで1件も流れない（headless: 位置 93 のまま・新しい store 15〜30件・画面上 0件）。
- 流しの入れ直し（`toggleFlowVisibility`）は `chatIndexFor(store.comments, 再生位置)` で位置を作る。ライブの再生位置（DVR の秒）とコメントの `t` の関係によっては、新しいコメントより先の位置になりうる（実機で入れ直しても直らなかったことの説明として有力・未検証）。
- 🔴 自動の取り直し（v2.13.1）は store を捨てないので、この不具合は起きない。🔄 だけで起きる。

## 3. 修正

- store に番号 `sid`（作るたびに増える）を持たせ、流しは `flowStoreSid[cardId]` にどの store の添字かを覚える。番号が変わったら、画面上の流しを消して `flowCursor` / `flowLastMs` を引き直す（ライブ: 開いた時点より後・アーカイブ: 再生位置）。
- 🔴 store そのものを覚えない（8-13節の破棄で配列が残るため）。番号だけ。キャッシュから戻した store には番号が無いので、流しが初めて読むときに付ける。
- ライブで流しを入れ直したら、読む位置は再生位置と突き合わせず「開いた時点より後」（`null`）。
- 版数: `APP_VERSION` 2.13.2・`APP_HISTORY` 48件・`debug_suite.js` v1.23.2（`D-N3` 48）。
