## 1. やること

`.players-grid` の列と列・行と行の隙間（gap 6px）につまみを重ね、ドラッグで**隣り合う2本のトラックだけ**を太く・細くする。
つまみのダブルクリックでその構成を均等に戻す。🔴 `order`・保存URL（`sync_url_*`）・`activeCardIds` には触れない。

## 2. 着手前に実コードで確かめたこと

| # | 確認 | 結果 |
| :-: | :--- | :--- |
| 1 | 列・行の指定 | `updateLayout()` が `grid-template-columns/rows` を `repeat(n, minmax(0, 1fr))` で書く。N=2 は向き（`layout2Dir`）とピンで分岐（ピン中は行 `2fr 1fr`） |
| 2 | ピン枠の配置 | 開始行・開始列を明示して 2×2 を占める（`pinAtRight` / `pinAtBottom`）。🔴 ピン枠の内側にはトラックの境目があっても**隙間が無い** |
| 3 | 枠の中身 | YouTube は iframe。🔴 iframe の上ではマウスの動きが親へ届かない → **ドラッグ中だけ iframe の `pointer-events` を切る** |
| 4 | 既存の幾何判定 | D-Y / D-Z は均等なトラックを前提に期待値を作っている → 利用者が比を変えていると誤判定する |
| 5 | アニメーション | `.player-card` に `transition: all 0.3s`。ドラッグ中は追従が遅れるので切る |

## 3. 設計の判断（①で決めること ─ 比をいつ捨てるか）

- 比は **構成の署名** ごとに `fr` の配列で持つ。署名 = `列数x行数` ＋ ピン中は `:pin`。N=2 は `n2:2x1` / `n2:1x2` / `n2:1x2:pin`。
- 🔴 **捨てない。構成が変わったらその構成で前に決めた比へ戻る（無ければ均等）。** 別の構成の比を流用すると列数の違う配列を当てはめて崩れる。
  - 賛成の根拠: 「9枠にして戻したら比が消えた」は不満になりやすい。署名ごとなら戻した時に復元される。
- 保存: `localStorage` の `sync_grid_ratios`（「全設定リセット」は `localStorage.clear()` なので一緒に消える）。
- 最小幅 80px（ドラッグでそれ以下にしない）。
- つまみはピン枠の上に出さない（隙間が無い区間は切って出す）。
- 一括コントローラーの出入り（`main-view` の padding が 0.3s で変わる）に `ResizeObserver` で追従する。

## 6. 再測（2026-10-02 実機の結果を受けて）

1回目の実機測定は自動判定がすべて合格し、目視の2件が不合格だった。

| # | 症状 | 原因 | 対処 |
| :-: | :--- | :--- | :--- |
| 1 | ダブルクリックで戻らない | 🔴 1回目の mouseup でつまみを作り直していた。ネイティブの `dblclick` は「2回とも同じ要素」でしか発火しない。D-S1 はつまみへ直接 `dblclick` を合成していたので見逃した（合成イベントが実機の発火条件を満たしていなかった） | 動かしていなければ作り直さない。加えて2回目の mousedown（450ms 以内・4px 以内）を自前でダブルクリックと判定する |
| 2 | 再読み込みで均等に戻った | **headless Chromium では再現しない**（保存も復元もされる）。原因は未確定 | D-S2 を新設し、実機で再読み込みをまたいで測る。失敗したときに原因を絞れるよう、保存値・メモリ上の値・署名・枠数・`style.gridTemplateColumns` を全部記録する |

- 利用者要望: 比を変えた構成のときだけ上部（枠数 ➕ の右）に **⊞**（均等に戻す）を出す。均等なら隠す。
- `debug_suite.js` v1.13.1:
  - D-S1: ダブルクリックを「毎回その座標にある要素へ送る」形に変更（`realDblClick`）。⊞ の出し入れと、⊞ で戻ることの判定を追加（27 → 31）。
  - D-S2（manual）を新設。`LS_RESUME` の `which: 'S2'` で D-M7 と振り分ける。
  - `VERSION_FOCUS` = `D-S1` → `D-Y1` → `D-Y12` → `D-S2`（再読み込みするので最後）。
- 負の検証: 旧コード（mouseup で作り直す・自前判定なし）を注入すると D-S1 が **不合格（27/31）**。2回のクリックは「別の要素（作り直された）」と記録される＝実機の症状を再現した。

## 7. 再測2（2026-10-02）

- 再測1の目視はすべて合格した（ダブルクリック・⊞・F5 / Ctrl+Shift+R 後に比が残る）。1回目の「再読み込みで均等に戻った」は再現しなかった。D-S2 の観測でも、実機の保存値とメモリ上の値が再読み込みをまたいで一致した。
- 🔴 **D-S2 が判定不能だった原因は基盤側の誤り。** 基準の列幅 c0 を、`resetGridRatios()` で均等へ戻す**前**に読んでいた。利用者が比を変えていた実機では c0 = [596, 708] になり、+70px の PC が不成立になった。headless は保存値が空なので通っていた。→ 戻した後に読み、PC に「均等であること」を足した（v1.13.2）。保存値を入れた状態でも headless で合格することを確かめた。
- 利用者要望: ローカル動画の履歴を押すと、`alert` の代わりにその枠の file input を同期的に `click()` する（`openLocalPicker`）。ファイル名は `title` に出す。パスから開くことと初期フォルダの指定はブラウザが許さないので行わない。
- D-Z2（manual）: file input の click を capture で捕まえて `preventDefault` し、選択画面を開かずに数える。PC は「直接 `click()` すると1回数えられる」。旧コード（alert）を注入すると不合格（1/3）になる。
