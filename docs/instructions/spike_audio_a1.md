# スパイク A1 指示書 ─ 枠ごとの音のレベルを測れるか

発行: 2026-10-21（Claude Code）
基点: `index.html` v2.11.2 / アドオン 2.11.1（**本番コードへの変更なし**）
読む仕様書: `get-dev-workflow`（1-4節・3-1-2節「スパイクに限り計測スニペット」）/ `get-protocol-spec`（4-2節 埋め込みの content script）
種別: **版数を切らないスパイク。** 成果物は `tests/spike_audio_a1.js`（埋め込みの中のコンソールに貼る計測コード）と `tests/test_spike_audio_a1.html`（用紙）。撤退はファイルの削除だけ。

## 1. きっかけ（利用者 2026-10-21）

各枠の実際の音量レベルを、比べやすく目で見えるようにしたい（発話の音量）。

## 2. 前提（実コードと仕組みで確かめたこと）

| # | 確認 | 結果 |
| :-: | :--- | :--- |
| 1 | 音の混ぜ方 | 各枠（YouTube の埋め込み）の音は**ブラウザが混ぜて** OS へ渡す。ブラウザの中には枠ごとの音が別々にある |
| 2 | A側から測れるか | **測れない。** 埋め込みは別オリジン（`www.youtube.com`）で、同一オリジンポリシーにより映像も音も読めない |
| 3 | 抜け道 | アドオンは v2.9.0 から各枠の埋め込みの中で動いている（`content_yt_embed.js`・`all_frames`）。そこで混ぜる前の音を測り、`SYNC_EMBED_*` と同じ経路で A側へ送れる見込み |
| 4 | 🔴 リスク | Web Audio で音を取り出すと、取り方によっては**その枠の音が出なくなる**（`createMediaElementSource` は通り道を付け替える。Firefox の `mozCaptureStream` は元の音を止める場合があるとされる）。埋め込みは利用者の操作を受けていないので `AudioContext` が `suspended` で始まり、付け替えると無音になるおそれもある |
| 5 | 測る位置 | 枠ごとの音量（`setVolume`）と YouTube の音量の均しを**掛けた後**か**前**かで意味が変わる。前で測る場合は `video.volume` を掛けて換算できる |

## 3. 計測コード（`audio-a1-1.0.0`）

埋め込みの中（コンソールの実行先を「Top」から埋め込みへ切り替える）で実行する。埋め込みの左上にパネルを出す。パネルを押すことが埋め込みへの操作になり、`AudioContext.resume()` が通る。

| ID | 録り方 | 通り道 |
| :--- | :--- | :--- |
| `D-Q1` | `mozCaptureStream()`（無ければ `captureStream()`）→ `createMediaStreamSource` → 解析だけ（出力へ繋がない） | 変えない |
| `D-Q2` | `createMediaElementSource(video)` → 出力へ繋ぐ ＋ 解析 | 🔴 付け替える（元に戻せない。最後にページを読み込み直す） |

- 各録り方で「そのまま 4秒 → `setVolume(半分)` 4秒 → `pauseVideo()` 2.5秒 → 再開」。50ms ごとに RMS（dB）と声の帯域（1kHz 中心のバンドパス）を測る。
- 判定: 取り出しを作れた・🔴 再生中に -60 dB 超・🔴 一時停止で無音（10%未満 ＝ 計測が音に反応している証拠）。記録: 音量を半分にしたときの差（約 -6 dB ＝ 音量を掛けた後 / 約 0 dB ＝ 前）・`AudioContext` の状態・`getVolume` と `video.volume` の比（YouTube の音量の均し）。
- 🔴 **主たる判定は利用者の耳**（測っている間も音が聞こえ続けたか）。用紙 R1a / R1b。
- `innerHTML` は使わない（YouTube の埋め込みは文字列での HTML 書き込みを禁じている）。

## 4. headless の確認（Chromium・偽の埋め込み）

`https://www.youtube.com/embed/…` を、音の鳴る `<video>`（440Hz＋1.2kHz の WAV・ループ）と偽の `#movie_player`（`video.volume = 0.8 × 音量/100` で YouTube の音量の均しを模す）に差し替えた検証台。

| 項目 | 結果 |
| :--- | :--- |
| 埋め込み以外で貼る | 「埋め込みの中で実行してください」と出て何もしない |
| `D-Q1` 写し取り | 合格 4/4。再生中 -13.1 dB・一時停止で 0%・**音量を半分にしても +0.1 dB**（＝音量を掛ける前の音） |
| `D-Q2` 付け替え | 合格 4/4。再生中 -15.0 dB・一時停止で 0%・**音量を半分で -6.0 dB**（＝掛けた後の音） |
| 用紙 | 計測コードの写しが原本と一致・3つの照合が合格 |

## 5. 結果の読み方（次の一手）

| 結果 | 次の一手 |
| :--- | :--- |
| A1 で音が消えず、レベルが取れる | A1 を採用。掛ける前の音なら `video.volume`（均しと枠ごとの音量を含む）を掛けて「実際に鳴っている大きさ」に換算する。アドオンの `content_yt_embed.js` に組み込み、レベルを A側へ送る（メッセージが増える → マイナー v2.12.0） |
| A1 で音が消え、A2 は消えない | A2 を採用（掛けた後の音なので換算が要らない）。ただし元に戻せないので、測る仕掛けを入れたら枠を読み込み直すまで外さない設計にする |
| どちらも音が消える／レベルが取れない | 埋め込みの中で測る案は撤退。代わりの案（例: YouTube の均し後の `video.volume` と動画ごとの音量の目安だけを出す）を検討する |
| `AudioContext` が `suspended` のまま | 操作なしでは動かない。本番では「測る」ボタンを埋め込みの中に出す等の設計が要る |

## 6. 測れなかった値・未確認

- 🔴 Floorp での挙動はすべて未測定（Chromium の結果は参考）。特に `mozCaptureStream` で元の音が止まるか、`AudioContext` が操作なしで動くか。
- 本番ではコンソールではなく content script（隔離された環境）から動かすことになる。隔離環境から Web Audio が使えるかは、組み込みの段で確かめる（必要なら `world: "MAIN"` で動かす）。
- 複数枠の同時計測の負荷は測らない（A1 は1枠）。
