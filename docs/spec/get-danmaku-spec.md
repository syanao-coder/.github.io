## 1. ニコニコ風コメント流し ★v2.7.0

チャット欄とは独立した、動画の上へコメントを流すオーバーレイ。
**チャット欄と併用でき、チャット欄を閉じていても動く**（動画だけ見たい人向けの主用途）。
UI は枠ヘッダーの `🌊`（`💬` の左隣）。状態は枠ごとに独立し `localStorage`（`sync_flow_map`）へ保存する。

### 1-1. 確定した定数（`FLOW`）

| 定数 | 値 | 根拠（2026-07-31 実測） |
| :--- | :--- | :--- |
| `durationMs` | **4000** | 9枠・6.7件/秒で fps最低 89.6・追い越し0・カクつきなし。**6000 は 54.5 まで落ち、体感でも3方式ともカクつく** |
| `maxLanes` | **0（＝枠に入るだけ）** | 9枠でも要間引き0%。上限を切る必要がない |
| `laneRatio` | **1.3**（レーン高 = `round(文字px × 1.3)`） | 16px → 21px |
| `maxOnscreen` | **40 / 1枠** | ラボの実測最大27の1.5倍。**実機9枠では各枠4〜9件**で、実運用では発動しない安全弁 |
| `fontPx` | 16 | |
| `gapPx` | 8 | 同じレーンの前後の最小すき間 |
| 間引き方式 | **先着優先で捨てる（T1）** | 下表 |
| 描画方式 | **rAF で毎フレーム `transform` を書く（D3）** | 下表 |

### 1-2. 🔴 実測で覆った前提（再提案しないこと）

**① 「CSS に任せれば軽い。rAF ループを新設しない」は誤り。**

9枠・密度6.7件/秒・同時表示243個で、**D3（rAF）の fps最低は D1/D2 より 36%高い**
（89.6 対 65.6 / 66.2 ─ 4000ms）。同時表示数・間引き率・追い越しは3方式とも同一なので、
差は純粋に描画コストである。

🔴 **1枠では3方式とも 99.8 で頭打ちになり、差はまったく出ない。**
**9枠で測らなければ分からない。** 描画方式を触るときは必ず9枠で比較すること。

理由: 243個が同時にアニメーションする状況ではブラウザ側の再計算がメインスレッドで走るため、
**JS で inline transform を書くほうが軽い。**

**② 「6.7件/秒なら間引きが必須」も誤り**（画面サイズによる）。

1レーンには複数のコメントが乗るため、収容数は **`レーン数 × (枠幅 + 平均幅) / 平均幅`**。
2560×947 の画面では **1枠 40レーン・収容467件に対し期待27件＝要間引き0%**、
**9枠でも8〜13レーンで足りた**。間引きは保険として持つだけでよい。

**③ 間引きは T1（満杯なら捨てる）を採用。** T2（最古を消して割り込む）は
**追い越しが多発し、画面の途中でコメントが消える**（実測で追い越し231回・目視でも確認）。
T3・T4 は T1 より落としすぎる。

詳細な計測表は `history_chat.md`。

### 1-3. 設計

| 項目 | 方式 |
| :--- | :--- |
| 時刻源 | **動画の再生位置**（実時間ではない）。250ms tick で読み、フレーム間は `performance.now()` で補間（上限400ms） |
| 一時停止 | `getPlayerState()` を毎フレーム見る。**1以外はすべて止める**（2=一時停止 / 3=バッファ中 / 0=終了） |
| 速度変更 | 補間に `currentPlaybackSpeed` を掛けるだけ。**全消しは不要**（再生位置が時刻源なので自動追従） |
| シーク | **全消しして `chatIndexFor()` でカーソルを出し直す。** 途中から繋げない |
| 動画差し替え | 全消し。`flowCursor` を 0 に戻す |
| 生成 | `pumpFlowProgress()`（250ms tick） |
| 移動 | `flowRafLoop()`。🔴 **全枠で1本だけ。枠ごとに9本立てない** |
| レーン選択 | 追い越しが起きないレーンを集め、**その中から無作為に選ぶ** |
| 本文描画 | 既存の `appendChatBody()` を再利用（絵文字対応 ＋ `innerHTML` 禁止を構造的に満たす） |
| 文字幅 | canvas で測る。**要素を足して `offsetWidth` を読むと1件ごとに強制レイアウトが走る** |

### 1-4. 🔴 罠（すべて実機で踏んだもの）

| 罠 | 内容 |
| :--- | :--- |
| `pointer-events: none` の省略 | **動画のクリックとシークバーの操作を層が全部奪う。** YouTube は iframe なので操作不能になる |
| `chatCursor` との共用 | **共用してはいけない。** `pumpChatProgress()` はチャット欄が非表示だと冒頭で抜けるため、共用すると閉じた瞬間に流しが止まる。逆に流しだけ動かすとチャット欄の一覧が飛ぶ |
| `pumpChatProgress()` に生成を相乗りさせる | 同じ理由で**不可**。別関数を同じ tick から呼ぶ |
| オーバーレイを一度置くだけ | `loadSingleYT()` が `container.innerHTML` でプレイヤーを差し込むため、**動画を読み込むたびに消える。** 毎tick自己修復する |
| レーン数が変わったら作り直す | **してはいけない。** 枠の高さは操作バーの出し入れ・YouTubeのコントロール表示・ピン留めでも変わる。全消しすると「一時停止したらコメントが消えた」ように見える。**減ったレーンのぶんだけ片づける** |
| 空きレーンの先頭を必ず選ぶ | 薄い動画では**常に最上段が空く**ため、コメントが1行目に集中してタイトル帯に重なる |
| 枠幅が変わったとき | 流れている途中の要素の移動量（`-(枠幅 + 本文幅)`）を**引き直す。** 引き直さないと途中で止まる／行き過ぎる |
| 250ms の位置比較だけで一時停止を判定する | 止めてから**最大0.5秒流れ続ける。** プレイヤーの再生状態を毎フレーム見る |
| 一時停止時に tick の値へ戻す | **止めた瞬間に巻き戻って見える。** 直近フレームで描いた位置を掴んで固定する |

### 1-5. ⛔ 恒久的な制約

**YouTube の全画面表示では流しは出ない。** 全画面は iframe 自身がネイティブに全画面化するため、
親側のオーバーレイは表示できない。**回避しようとしないこと。** 解除すれば復帰する（実機確認済み）。

### 1-6. 実測値（実機 / 2026-07-31 / Firefox 153 / 2560×947）

| 条件 | 値 |
| :--- | :--- |
| 9枠時の1枠のレーン数 | **8本**（ラボは枠のみで13本。実機はカードのヘッダーぶん縦が短い）。**2026-08-02 に別PCで再確認しても8本** |
| **1枠時のレーン数** ★2026-08-02 | **26本**（レイヤー高 557px / `fontPx` 16） |
| 9枠・`VID_HEAVY`・流しオン時の各枠の同時表示 | 4〜9件（上限40には遠い） |
| **9枠・`VID_HEAVY` の同時表示（別区間）** ★2026-08-02 | **全9枠が20件ちょうど・合計180件。** 同じ動画を同じ位置で再生しているため、**その区間のコメントが1件も間引かれずに全部流れている**ことを示す（v2.7.0 の「要間引き0%」と整合） |
| CPU（Firefox プロセス合計）9枠再生のみ | **約70%**（2026-07-31 / PC-A） |
| CPU 9枠 ＋ 流し9枠 | **約84%**（2026-07-31 / PC-A）─ **流しの上乗せは約14ポイント** |
| コマ落ち | なし（目視。2026-08-02 の9枠でも同じ） |

🔴 **CPUの基準値（約84%）は 2026-07-31 の PC-A のもの。**
2026-08-02 の検証は**別の高性能PCで行われ最大15%**だったが、**この値は基準値にできない。**
負荷を測るときは**前回と同じPCを使うか、基準値ごと取り直すか**を先に決めること（`/get-chat-feature-spec` 10節）。

### 1-7. 取得の開始

**流しをオンにした時点でも取得を始める**（チャット欄を開かない使い方が主用途のため）。
`requestChatArchive(cardId, videoId, quiet)` の第3引数で**案内文の描画だけを省く**。
🔴 `chatInflight` の同期セット（非同期のキャッシュ照会より前）はそのまま通すこと。

## 2. コメント流しの調整UI ★v2.7.1

`FLOW` の一部を設定から変更できるようにしたもの。**設定は全枠共通（グローバル）**で
`localStorage` へ保存する。

**置き場所は トップバーの独立メニュー**（★v2.7.2 で ⚙ から移した）。
ボタンは `💬 コメント設定`（`id="topCommentBtn"`）、パネルは `id="commentMenu"`。
**トップバーの並びは左から `[💬 コメント設定] [📂 マイリスト・セッション] [▼ 設定メニュー]`。**
パネルの構造・確定値は **`/get-ui-spec` 1節**。

中身の並び: 見出し `💬 コメント設定` → 🌊 コメント流しの表示（全枠共通）7項目 ＋「既定値に戻す」
→ 注記 → コメントのキャッシュ ＋「すべて削除」→ 注記。

⚠️ **「🎨 UI・デザイン設定」に残したものを、あとから移さないこと**（v2.7.2 で選別済み）:
全体のUIサイズ / チャット配置方向 / 全枠のチャットを表示 / チャット欄の幅を全枠で連動 /
コメント取得用タブ / 全設定・保存URLをリセット。
**チャット系3つはコメント関連だが「枠レイアウトの設定」としての意味が強い**（利用者判断 2026-08-02）。

⚠️ **移設で `id`・`oninput`/`onclick`・関数・定数は1つも変えていない。** 変えると
`applyFlowSettingsFromUI()` などの `getElementById` が全部外れる。

### 2-1. 設定できる項目

⚪ **7項目すべてに `?`（ホバーで解説）が付いている** ★v2.8.2（`/get-ui-spec` 3節）。
🔴 **解説の文面は本節の確定値が正本。** 変えるときは両方を直すこと。
⚠️ **`?` は `label` の内側末尾。ただし「文字を縁取る」だけは `label` の外側**
（チェックボックスへクリックが転送されるため）。**解説の全文は `history_protocol.md` 24節。**

| 表示名 | `FLOW` のキー | 範囲 | 刻み | 既定 | `localStorage` キー |
| :--- | :--- | :--- | ---: | ---: | :--- |
| 同時表示数の上限 | `maxOnscreen` | 5〜100件 | 5 | 40 | `sync_flow_max_onscreen` |
| 画面を横切る時間 | `durationMs` | **2000〜12000ms** ★v2.7.2拡大 | 100 | 4000 | `sync_flow_duration_ms` |
| 文字サイズ | `fontPx` | 10〜32px | 1 | 16 | `sync_flow_font_px` |
| **文字の色** ★v2.7.2改称 | `color` | カラーピッカー | ─ | `#ffffff` | `sync_flow_color` |
| 不透明度 | `opacity` | 0.2〜1.0 | 0.05 | 1 | `sync_flow_opacity` |
| 表示位置の範囲 | `areaRatio` | 0.2〜1.0 | 0.05 | 1 | `sync_flow_area_ratio` |
| 文字を縁取る | `shadow` | on / off | ─ | on | `sync_flow_shadow` |

⚠️ **`laneRatio` / `gapPx` / `maxLanes` / `emojiRatio` はUIに出さない。** 利用者が意味を判断できない。
⚠️ **描画方式（D1/D2/D3）も設定項目にしない。** 3経路を本番に持つと、不具合が出たときの
切り分けが3倍になる（v2.7.0 で決定）。

### 2-2. 関数の分担

| 関数 | 役割 |
| :--- | :--- |
| `applyFlowSettingsFromUI()` | スライダー → `FLOW`。数値表示を更新し `saveFlowSettings()` を呼ぶ。各入力の `oninput` から呼ばれる |
| `updateFlowSettingLabels()` | 数値表示（`40件` / `4.0秒` / `16px` / `1.00` / `上100%`）を書く |
| `syncFlowSettingUI()` | `FLOW` → スライダー。起動時の復元と「既定値に戻す」の両方で使う |
| `resetFlowSettings()` | `FLOW_DEFAULTS` を書き戻す。「既定値に戻す」ボタン |
| `saveFlowSettings()` / `loadFlowSettings()` | `localStorage` への保存・復元。前者は `saveSettings()` からも呼ばれ、後者は `loadSavedSettings()` の冒頭で呼ばれる |

### 2-3. 🔴 実装上の決めごと

| 決めごと | 理由 |
| :--- | :--- |
| **`oninput` で反映する（`onchange` にしない）** | ドラッグ中に反映されないと「効いていない」と誤認される。※チェックボックスだけは `onchange`（ドラッグが無いため） |
| **スライダーの `oninput` からは `saveFlowSettings()` だけを呼ぶ** | ドラッグ中は毎フレーム発火する。`saveSettings()` 全体だと1回で17項目を `localStorage` へ書く |
| **設定変更時にレーンを作り直さない** | `flowEnsureLanes()` の「減ったぶんだけ片づける」実装に任せる。全消しすると「一時停止したらコメントが消えた」ように見える（1-4節） |
| **見た目は `flowSpawn()` で生成時に焼き付ける** | 色・不透明度・文字サイズは**新しく出るコメントから**反映される。既存要素を書き換えると幅が変わり移動量の再計算が要る。**仕様として許容する**（利用者了承済み 2026-08-02） |
| **`areaRatio` はレーン数の計算に掛ける** | `Math.floor((layer.clientHeight * FLOW.areaRatio) / lh)`。動画の字幕や顔が隠れるのを避けるための設定 |
| **`syncFlowSettingUI()` を復元時に必ず呼ぶ** | 値だけ戻してスライダーが既定位置のままだと、次に触った瞬間に値が飛ぶ |

⚠️ **「画面を横切る時間」は値が大きいほど遅く流れ、かつ重くなる**（画面に残る数が増えるため）。
ラベルを「速さ」にすると利用者が逆に理解するので、**単位つきで「画面を横切る時間（秒）」**とする。

### 2-4. UI上の配置 ★v2.7.2

7項目はすべて **ラベル `width:150px` ＋ 入力 `width:160px` ＋ 数値表示 `width:52px`** で統一する。
実測（2026-08-03 / 幅420pxのパネル内）: ラベル left 296 / 入力 left 458 / 数値 left 630 が全項目一致
（`flowColor` のみ 456 ＝ `input[type=color]` の描画差）。

⚠️ v2.7.1 では**不透明度だけ**スライダー110px・数値40pxで「文字の色」と同じ行にあり、左端が揃っていなかった。
v2.7.2 で独立行にして揃えた。**新しい項目を足すときもこの3つの幅に合わせること。**

⚠️ 「文字を縁取る」は「表示位置の範囲」と同じ `control-row` にあり、幅420pxでは折り返して独立行に見える。
**実害がないのでそのままにしてある。**

⚠️ 「画面を横切る時間」の説明文にある **`（6.0秒以上はカクつきます）` は据え置き**（2026-08-03 判断）。
上限を12秒に広げても、6.0秒は 1-1節の実測（fps 54.5 まで低下）に基づく値なので誤りにならない。
🔴 **12秒での fps・CPU は一度も測っていない**（`/get-chat-feature-spec` 9節の申し送り）。

### 2-5. 実測から確定したこと

🔴 **レーン数は固定値ではない。レイヤー高で決まる。**
同じ1枠でも計測ごとに **232 / 260 / 527px** とばらついた（窓のサイズ・YouTubeのコントロール表示・
チャット欄の開閉で変わる）。**レーン数を報告するときはレイヤー高を必ず併記すること。**

一定なのは **レーン高 = `fontPx` × `laneRatio 1.3`**（`fontPx` 16 なら 21px）のほう。
`areaRatio` はこれに掛かる: `Math.floor((レイヤー高 × areaRatio) / レーン高)`。
`fontPx` を上げるとレーンは減る。日付ごとの測定値は `history_chat.md`。

`maxOnscreen` は指定値で頭打ちになり、戻すと同じ区間で増える。
**ドラッグ中に一定間隔でサンプリングして「0件になった回数」を数えると、
レーンの作り直しが起きていないことを確認できる**（2版で計159回・0回）。

## 3. ライブ配信での流し → `/get-chat-feature-spec` 1-6節が正本
