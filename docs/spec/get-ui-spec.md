## 1. トップバーのメニュー構造 ★v2.7.2 / 4枚目を v2.7.3 で実証

コメント系設定を⚙から独立させるために新設した、**ボタン直下に出る幅の狭いパネル**。
`.settings-container`（画面幅いっぱいに降りてくる既存2枚）とは**別系統**である。

🔴 **次にトップメニューを増やすときは、この節の確定値に従うこと。**

#### なぜ全幅パネルにしないか

**画面幅いっぱいのパネルは動画とコメント流しを覆い、効果を見ながらの調整ができなくなる。**
実測（2026-08-03 / 1枠）: 枠1の動画領域 818×472 に対し**重なり 43.5%**、調整中も31件が流れて見えていた。

#### 確定値（2026-08-03 実測 / Firefox / 画面幅 1059px）

| 項目 | 値 |
| :--- | :--- |
| 幅 | `width: 420px; max-width: calc(100vw - 20px);`（外形420px ＝ 画面幅の39.7%） |
| 高さ | `max-height: 70vh; overflow-y: auto;`（実測403px ＝ 70vh ちょうど。**縦スクロールは出る。正常**） |
| 🔴 `box-sizing` | **`border-box`（必須）** ─ 下記 |
| 位置 | `position: absolute; top: calc(100% + 6px); right: 0;`（ボタン bottom 33 → パネル top 39。右端は完全一致） |
| `z-index` | **120**（`.settings-container` が100、`.top-bar` が101。両方を上回る必要がある） |
| 開閉 | `display: none` ⇔ `.open { display: block }` |
| 見た目 | `.settings-content` と同系統（`var(--panel-bg)` / `1px solid #00ffcc` / `border-radius 6px` / `padding 12px` / `backdrop-filter: blur(10px)` / `box-shadow: 0 10px 30px rgba(0,255,204,0.15)`） |

🔴 **`box-sizing: border-box` を書き忘れると `max-height` が効かない。**
既定の `content-box` では `padding 12px×2 + border 1px×2 = 26px` が `max-height` の**外側**に乗るため、
`70vh` 指定でも実測 **429px**（= 403 + 26）になる。**ブラウザに描かせるまで分からない類の抜けで、
机上のレビューでは出ない**（v2.7.2 の手戻り1件目）。

**内容領域は 420 − 26 = 394px。** 既存の `control-row`
（ラベル150 + 入力160 + 数値52 + gap20 = 382px）が折り返さずに収まる上限である。
**これより広い部品を入れると折り返す。**

⚠️ **`.settings-container` の `transform: translateY(-100%)` + `pointer-events:none` 方式を流用しないこと。**
あれは「隠れていても存在してマウスを吸う」作りを回避するための仕組みで、
`display:none` のほうが単純で安全。

#### 🔴 アンカーは新ボタンだけを包む `<span>` に持たせる

```html
<span class="topmenu-anchor">   <!-- position: relative; display: inline-flex; -->
  <button id="topCommentBtn" class="settings-toggle-btn" onclick="toggleCommentMenu()">💬 コメント設定</button>
  <div class="topmenu-dropdown" id="commentMenu"> ... </div>
</span>
```

🔴 **`.top-bar` に `position: relative` を足してはいけない。**
既存の `.settings-container` 2枚が `.top-bar` を基準にしてしまい、
`top:35px` / `width:100%` の解決先が変わって**位置と幅が壊れる。**

#### 🔴 外側クリックでは閉じない

閉じるのは「もう一度ボタンを押す」「他のトップメニューを開く」の2つだけ。
**`document` への click リスナーを足さないこと。**
動画をクリックした瞬間に閉じると、動画を見ながらスライダーを動かせなくなる
（実機確認済み: 動画上をクリックしても `open` と `active` が保持される）。

#### 排他制御は `closeTopMenus()` に集約する

2枚のときは互いを名指しで閉じ合っていたが、3枚目を足すと組み合わせが 3×2 に増えて閉じ忘れが出る。

```js
const TOP_MENUS = [
    { panel: 'sessionContainer',  btn: 'topSessionBtn' },
    { panel: 'settingsContainer', btn: 'topSettingsBtn', arrow: 'topSettingsArrow' },
    { panel: 'commentMenu',       btn: 'topCommentBtn' }
];
function closeTopMenus(exceptId) { /* open を外す ＋ ボタンの active を外す ＋ 矢印を ▼ に戻す */ }
```

3つの toggle はいずれも **「開くかどうかを先に決める → `closeTopMenus(null)` で全部閉じる →
開く場合だけ開く」**の形にする。これで「同時に1枚以下」が構造的に保証される。

⚠️ **`active` の付け外しを忘れると、パネルは閉じたのにボタンだけ光ったままになる。**
この構造で最も出やすい壊れ方なので、テストでは `open` だけでなく **`active` も数えること。**

⚠️ **`toggleSessionMenu(false)`（強制的に閉じる）の副作用範囲が v2.7.2 で広がった。**
v2.7.1 までは「セッション＋設定」を閉じていたが、**いまはコメントメニューも閉じる**。
呼び出し元は `controller.html` のセッション読込後の1箇所のみで、意図と合致するため容認している。

#### 開くときの副作用

| メニュー | 呼ぶもの |
| :--- | :--- |
| 📂 マイリスト | `updateSessionListUI()` |
| ▼ 設定メニュー | **なし**（v2.7.1 まであった `refreshChatCacheStat()` は 💬 へ移した） |
| 💬 コメント設定 | `refreshChatCacheStat()` |

`debug_suite.js` が **`🐞 デバッグ` を4枚目として動的に生成し、上記の確定値のまま成立した**
（2026-08-04 / Firefox / 画面 1059×576）。**20遷移すべて合格・クリックが被覆された回数0。**

## 2. 再生可否の確定と枠内通知 ★v2.7.4

再生できなかった枠に、その場で理由の候補を出す仕組み。
**再生できるのに出す（誤表示）ことを最も強く避ける設計である。**

### 2-1. なぜ「待って確定させる」必要があるか

`onError = 150` は**再生できる場合にも出る**（`/get-protocol-spec` 8節）。受けた瞬間に表示すると誤表示になる。
`getDuration()` / `getVideoData().title` も取れる回と取れない回があり方向が一定しない。
**残る手がかりは `getPlayerState()` と `getCurrentTime()` の実際の進行だけ。**

### 2-2. 確定の流れ

```
onError 受信
  → 確定タイマーを起動（1秒ごとに見直す）
  → ▶一括再生 が押されるまで待つ（isPlayingRequest が false の間は確定しない）
  → 押されてから 10秒（PLAYER_VERIFY_MS）
  → getPlayerState() が 1、または getCurrentTime() > 0.5 なら「再生できた」→ 何も出さない
  → そうでなければ「再生できなかった」→ 枠内に通知を出す
```

**途中で `onStateChange` が `1`(playing) を返した時点で確定を打ち切り、通知を消す。**

### 2-3. 確定値

| 定数 | 値 | 意味 |
| :--- | ---: | :--- |
| `PLAYER_VERIFY_MS` | **10000** | ▶が押されてから確定するまで。実測 6.2秒（5-A3）に余裕を持たせた値。**短くしないこと** |
| `PLAYER_VERIFY_POLL_MS` | **1000** | 再生の指示を待つ間の見直し間隔 |
| `PLAYER_VERIFY_WAIT_MAX_MS` | **600000** | ▶が押されないまま待つ上限（10分）。超えたら黙って諦める |

| 状態変数 | 内容 |
| :--- | :--- |
| `playerErrorCode[cardId]` | 直近の `onError` のコード |
| `playerStateLog[cardId]` | 🔴 **`{ state, at }` の配列**（上限200件）。**件数だけでは何が来たか分からず切り分け不能になる** |
| `playerVerifyTimer[cardId]` | 確定用のタイマーID |
| `playerVerifyArmedAt[cardId]` | `onError` を受けた時刻 |
| `playerVerifyDeadline[cardId]` | 確定予定時刻 |
| `playerReadyDone[cardId]` | `onReady` の初期化を済ませたか |

### 2-4. 🔴 成功シグナルは `1`(playing) だけ

**`3`(buffering) を成功に数えてはいけない。** メンバー限定・保護オンで再生できないときの
状態遷移は **`[3,-1]`** であり、`3` は来る（2026-08-07 実測 / `/get-protocol-spec` 8節の表）。
`3` を成功に数えた実装では**通知が一度も出なかった。**

### 2-5. 🔴 再生が指示されるまで確定しない

本体は自動再生しない（`playerVars` に `autoplay` が無い）。
▶一括再生 を押す前に確定すると、**再生できるメンバー限定動画でも通知が出てしまう。**
`isPlayingRequest` が `true` になるまで、1秒ごとに確定を先送りする。

⚠️ **ただしメンバー限定動画は、読み込んだだけで埋め込み側が再生を始めることがある**
（2026-08-07 実測: 読み込み2.5秒後に位置 1.4〜1.9）。
このため「▶を押さない状態」を作りたい検証では、**存在しない動画IDを使うこと。**

### 2-6. 通知の要素構造

| 項目 | 値 |
| :--- | :--- |
| id | `playerNotice_<cardId>` / 本文は `playerNoticeBody_<cardId>` |
| 🔴 親要素 | **`wrapper_<cardId>` の直下**（`playerContainer_*` の**外**） |
| なぜ | `loadSingleYT()` が `container.innerHTML` でプレイヤーを差し込むため、**中に置くと読み込みのたびに消える** |
| `position` | `absolute`（`top: 8px; left: 8px`）。**枠の高さを押し出さない**（実測 443px → 443px） |
| `z-index` | **12**（流し層2・ローカル操作バー9より前） |
| 閉じる | 右上の `✕`（`.player-notice-close`）→ `hidePlayerNotice(cardId)` |
| 生成箇所 | `generatePlayerNoticeHTML(cardId)` を `createPlayerCard()` と `restorePlayerCardFromState()` の**両方**で挿入 |

### 2-7. 🔴 文面でブラウザ名を断定しない

「Floorp では再生できない」は 2026-08-07 に**本番コントローラーで再生できることが確定して覆っている**（`/get-protocol-spec` 8節）。

```
⚠️ 再生が始まりませんでした（エラーコード: <code>）
メンバー限定などの制限がかかっている可能性があります。
・アドレスバー左の盾のアイコンから「このサイトでは保護を無効にする」を選び、再読み込みしてください
・YouTube にそのチャンネルのメンバーとしてログインしていますか
・別のブラウザで開くと再生できる場合があります
```

⚠️ **エラーコードから理由は断定できない**（存在しない動画IDでも 150）。
文面が「メンバー限定**など**の制限」と幅を持たせているのはこのためで、**コードによる分岐を足さないこと。**
⚠️ 存在しない動画のときは文面が的外れになる。**言い回しでしか対処できない。**

### 2-8. 🔴 後始末は `resetPlayerDiagnostics()` に集約する

タイマー・エラーコード・状態遷移・`playerReadyDone`・通知の表示を**まとめて捨てる。**
**個別に `delete` を書かないこと**（v2.7.1 で `cardUrls` の落とし忘れが2経路出ている）。

呼び出しは**7経路**。**1つでも欠けると、次に読み込んだ動画で誤って通知が出る。**

| # | 関数 | きっかけ |
| :-: | :--- | :--- |
| 1 | `loadSingleYT()` | 新しい動画を読み込む |
| 2 | `restorePlayerCardFromState()` | セッション復元 |
| 3 | `handleLocalSelect()` | ローカル動画に差し替え |
| 4 | `destroyPlayerCard()` | 🗑 / 枠数を減らす |
| 5 | `resetPlayer()` | 🧹 |
| 6 | `loadSession()` | 一括復元（グリッドごと作り直し） |
| 7 | `clearAllSettings()` | 全設定リセット |

⚠️ **指示書が挙げていたのは4経路で、実コードには7経路あった。** 経路の数を前提にしないこと。

### 2-9. `onReady` の冪等化

`onReady` は複数回発火しうる（`/get-protocol-spec` 8節）。**両経路とも `playerReadyDone[cardId]` で2回目以降を無視する。**
冪等化しないと、復元経路では**保存位置への `seekTo` が2回走る。**

実測（2026-08-07 / セッション復元 / 枠1つ）: `onReady` 1回 / 初期化 1回 / `seekTo` 1回。
⚠️ **この回は二重発火が再現しなかった。** 冪等化そのものは `D-E1` で単体判定している。

## 3. 設定の解説（?マーク）と独自ツールチップ ★v2.8.2

設定の横に `?` を置き、マウスを乗せると「その設定で何が起きるか」を2〜4行で出す。

### 3-1. 🔴 `title` 属性を使わない理由

| | `title` 属性 | 独自ツールチップ |
| :--- | :--- | :--- |
| 表示まで | **1〜2秒待たされる** | すぐ出せる |
| 長文・改行 | **効かない** | `white-space: pre-wrap` で整形できる |

⚠️ **既存ボタンの `title` は33箇所あるが、そのまま残している。** 置き換えは範囲外（困っていないため）。

### 3-2. 🔴 最大の罠 ─ パネルの `overflow-y: auto` で切れる

設定パネルは `max-height: 70vh; overflow-y: auto`（1節）。
**その中に置いたツールチップは、はみ出した部分が切り取られる。**

🔴 **`document.body` の直下へ置き、`position: fixed` で座標を指定すること。**
親要素の中に相対配置すると必ず切れる。

⭐ **実測**（2026-08-18 / 画面 1248×939 / Floorp）: 💬 コメント設定の8項目のうち
**4項目でツールチップがパネル矩形の外へ出ていた**（最大 `chatCache` = **149px** /
`flowShadow` 25px / `flowMaxOnscreen`・`flowDurationMs` 各 11px）。**画面外へ出たものは0件。**

### 3-3. 確定値

| 対象 | 値 |
| :--- | :--- |
| `.help-q`（?マーク本体） | `14 × 14px` / `margin-left: 5px` / `border-radius: 50%` / `font-size: 0.62rem` / `cursor: help` / `display: inline-flex` |
| `#helpTip` の親 | 🔴 **`body`（必須）** |
| `position` | 🔴 **`fixed`（必須）** |

## 5. ピン留め時のグリッド配置 ★v2.8.5

### 5-1. 何を直したか

**6枠のうち末尾に近い枠をピン留めすると、2段目の右端に穴が空き、
ピン枠が存在しない4行目へ落ちてグリッドの外へはみ出していた。**

`.players-grid` は `grid-auto-flow: dense` だが、
🔴 **dense は小さい項目を後から穴に詰めるだけで、大きい項目を前へ動かさない。**
開始位置を持たないピン枠は `order` の位置で自動配置されるため、
先に 1×1 が並ぶと 2×2 の入る場所が無くなり、暗黙の行が作られていた。

🔴 **先頭の枠をピンしたときは崩れない**（`order` が 1 なので dense でも最初に置かれる）。
**末尾に近いほど起きる。**
🔴 **この不具合を検出するテストは必ず末尾の枠をピンすること。**
実測（2026-09-07）: 先頭枠では**はみ出し0 / 穴0 / 未解決0 ＝ 修正前でも合格してしまう。**

### 5-2. 直し方（確定値）

`updateLayout()` のカード走査で、**ピン枠にだけ開始位置を明示する**（それ以外は `span 1`）。

開始行・開始列を書くだけで、**`order` に一切触れずにピン枠を固定できる。** 残りは dense が自動的に埋める。

🔴 **v2.8.7 で開始位置は4隅から選べるようになった（左上固定ではない）。値の決め方は 8節。**

### 5-3. 🔴 `order` を書き換えてはいけない

**ピン留めするだけで保存URLが入れ替わる**（v2.7.1 で直した「消したはずの動画が復活する」の再発）。
`activeCardIds` も `order` から作られるので**枠の同定にも影響する。**
🔴 **`D-Y4` がこの退行を検出する判定である。**

## 6. グリッドが画面より高くなり下が切れる ★原因確定 2026-09-08 / ⚪ **v2.8.6 で修正済み**

**行数が増えるとグリッド自体が画面より高くなり、下が切れる。**
🔴 **`body` に `overflow: hidden` があるためスクロールバーも出ず、操作もできない。**

🔴 **空の枠でだけ起きる。** 動画を読み込んだ枠は iframe が絶対配置されるため

`.player-header` は**通常フローにあり**（`position: relative` / `flex-shrink: 0`）、
ホバーで `height: 0` → `var(--header-height)` になって中身を**押し下げる。**

🔴 **覆いかぶさるのではない。** ただし**押し下げられた結果として入力欄が可視領域の上へはみ出し、
そこへ `z-index: 10` のヘッダーが重なるため、最終的には被覆される。**
実測の当たり判定は **`blocked: covered / div.player-header`**。

⭐ **利用者の「せり出してくることによって隠れる」という表現は、結果としては正確だった。**
🔴 **利用者の言葉を実装の都合で読み替えると取りこぼす**（鉄則 #41 と同じ構造）。

**潰れる順序**

| # | 段階 |
| :-: | :--- |
| 1 | 中央寄せ領域が **`flex: 1 1 auto; min-height: 0`** なので **0 まで縮む** |
| 2 | 縮むと `justify-content: center` のはみ出しが上下へ均等に出る。🔴 **上方向のはみ出しはスクロールでは到達できない**（`scrollTop` は負にできない） |
| 3 | 外箱の **`padding: 20px`**（上下で 40px）が残り高をさらに削る |
| 4 | **履歴帯は `flex: 0 0 auto` で縮まない**ため、履歴があるとさらに早く潰れる |

⚠️ **主因は 1 であって 3 ではない。** padding は副因である。

### 7-2. 対処（v2.8.6 / `generatePlaceholderHTML()` のインライン2宣言のみ）

| 対象 | v2.8.5 | v2.8.6 |
| :--- | :--- | :--- |
| 外箱の `padding` | `20px` | `8px 20px`（**左右は変えない**） |
| 中央寄せ領域 | `flex: 1 1 auto; min-height: 0` | 🔴 **`flex: 1 0 auto`** |

**`flex-shrink` を 0 にすると領域は content 高より小さくならず、入力欄は必ず可視領域の先頭に来る。**
あふれた分は外箱（`overflow-y: auto`）のスクロールで到達できる。

### 7-3. 実測（手動1列 / ホバー相当 / 入力欄のはみ出し ─ 0 なら完全に見えている）

| 枠数 | 枠高 | v2.8.5 相当 | v2.8.6 |
| :-: | ---: | ---: | ---: |
| 3枠 | 298px | 0px | **0px** |
| 6枠 | 146px | **14px** | **0px** |
| 9枠 | 95px | **14px** | **0px** |

🔴 **症状が出るのは枠高 146px 以下。298px では出ない。**
⚠️ **空枠だけの症状である。** 動画を入れた枠では出ない（iframe が絶対配置されコンテンツ寄与がほぼ0になる）。
⚠️ 測定機の**動画履歴は14件**あり、履歴帯が存在する状態で測れている。

### 7-4. ⚠️ この設計で捨てたもの

**履歴帯は `flex: 0 0 auto` のままで縮まない。** 薄い枠ではスクロールしないと履歴帯が見えない。
🔴 **意図どおりである**（v2.8.6 は入力欄を優先する設計）。**直さないこと。**

## 8. ピン枠の位置を4隅から選ぶ ★v2.8.7

ピン留め中の枠の **◀▶** は、枠の並べ替えではなく**ピン枠を置く隅の移動**として働く。
順序は **左上 → 右上 → 左下 → 右下**（▶ で前進 / ◀ で後退）。既定は左上。**端では止める**（循環しない）。

### 8-1. 🔴 `moveCard()` の本体へ入らせないこと

`moveCard()` は `order` の入れ替え → `activeCardIds` の再計算 → `resaveUrlsBasedOnOrder()` と連鎖する。
ピン中に本体へ1度でも入ると **`localStorage` の `sync_url_1..N` が書き換わり**、
v2.7.1 で直した「消したはずの動画が復活する」の再発になる。

```js
function moveCard(cardId, direction) {
    const target = document.getElementById(cardId);
    if (target && target.classList.contains('is-main')) { movePinCorner(direction); return; }
    ...
}
```

⚠️ **この早期分岐は「押された枠自身がピン中のとき」だけに効く。**
ピンしていない他の枠の ◀▶ は従来どおり並べ替えとして動く（意図した仕様 / `D-Y10` の PC で実証）。

### 8-2. 🔴 選べる隅は構成から毎回計算する。固定の4状態にしてはいけない

開始位置は 右上 = `cols - spanCol + 1` / 左下 = `rows - 1` で、`spanCol = min(2, cols)`、ピンは常に2行を占める。
このため**構成によっては隅が退化して同じ場所になる。**

| 条件 | 退化 | 起きる構成 |
| :--- | :--- | :--- |
| `cols <= 2` | 右 ＝ 左（開始列が1） | **手動2列**・手動1列 |
| `rows <= 2` | 下 ＝ 上（開始行が1） | **3枠＋ピン（3列2行）** |

退化した軸は状態から外す（`canPinRight()` / `canPinBottom()`）。
状態は「右か（`pinAtRight`）」「下か（`pinAtBottom`）」の2軸で持ち、
表示順の番号は `(下?2:0) + (右?1:0)` で 0=左上 / 1=右上 / 2=左下 / 3=右下 に対応する。

| 構成 | 列×行 | 選べる隅 | ▶ を押したときの並び |
| :--- | :-: | :-: | :--- |
| 6枠・自動 | 3×3 | 4 | `r1c1` → `r1c2` → `r2c1` → `r2c2` |
| 9枠・自動 | 4×3 | 4 | `r1c1` → `r1c3` → `r2c1` → `r2c3` |
| 3枠・自動 | 3×2 | **2** | `r1c1` → `r1c2` |
| 6枠・手動2列 | 2×5 | **2** | `r1c1` → `r4c1` |
| 6枠・手動1列 | 1×9 | **2** | `r1c1` → `r8c1` |

⚠️ 実機で自動判定しているのは **6枠・自動のみ**（`D-Y11` / `D-Y12`）。他の構成は計算と目視（1列）だけ ─ `/get-protocol-spec` 11節 持ち越し9。

### 8-3. 決めごと

| 項目 | 決定 | 理由 |
| :--- | :--- | :--- |
| 端 | **止める**（循環しない） | 既存の `moveCard()` が端で早期 `return` する作法に合わせた。◀ で戻れる |
| ピンを外したとき | **左上へ戻す** | 保持すると次にピンしたとき前回の隅に出て驚く |
| `localStorage` | **保存しない** | 🔴 **ピン状態そのものが保存されていない**（`togglePin()` は DOM のクラスを触るだけで、`saveSettings` にもセッションにも入らない）。位置だけ永続化すると揃わない |
| `order` | **一切触れない** | 5-3節 |

### 8-4. グリッドの形は `computeGridShape()` に集約した

`updateLayout()` と `movePinCorner()` の両方が同じ関数を読む。
🔴 **`logicalCount = N + 3` と自動列数のしきい値は v2.8.6 から1文字も変えていない。**
変えると全枠数の見た目が動く。`N < 3` は `null` を返す（`N` が 1・2 は `updateLayout()` の専用経路）。

### 8-5. アイコン（★v2.8.7）

ピン留めボタンは **📌 → ⤢**。🔴 **クラス名 `.pin-btn` は変えない**（`debug_suite.js` の `pinBtnOf()` /
`clearPins()` がこのクラス名で引いており、変えると `D-Y` 群が全滅する）。
字面は **1.3倍**（`font-size: 1.3em`）。
🔴 **`line-height` を `0.77`（≒ 1/1.3）にして行ボックスの高さを元と同じに保つこと。**
`font-size` だけ上げるとボタンが高くなり、ヘッダー高が変わって**薄い枠の可視領域が減る**（7節）。
実測（2026-10-02 / `D-Y7`）: 1.3倍にした後も **ヘッダー 38px / 枠 94px / 可視 54px で不変。**
⚠️ 利用者の評価は「まだ小さい」→ **v2.8.8 で全ボタンを 1.5倍にそろえ、⤢ 個別の指定は外した（9節）。**

## 9. ヘッダーのボタンと一括コントローラーの出し方 ★v2.8.8

### 9-1. 🔴 ヘッダーの高さは固定値。壊れ方は「横幅でボタンが切れる」

ホバー時の `.player-header` の高さは `var(--header-height)`（`30px × --ui-scale` ＝ 中で 37.5px）の**固定値**で、`overflow: hidden`。
**中のボタンを大きくしてもヘッダーは伸びない。** はみ出したボタンは切れて見えなくなる。
🔴 **縦より横が先に壊れる。** 狭い枠（9枠・3〜4列）ではボタンの合計幅がヘッダー幅を超え、右端の ◀▶ が押し出される。
`debug_suite.js` の `D-Y13` が、9枠（最も狭い枠）でヘッダーの矩形からはみ出したボタンを数える。

### 9-2. 確定値

| 対象 | 指定 | 理由 |
| :--- | :--- | :--- |
| `.header-action-btn` / `.delete-btn` | `font-size: calc(var(--header-font) * 1.5)` / `line-height: 0.667` | 字面を 1.5倍にし、行ボックスの高さは元のまま（ボタン高 25px） |
| 同上 | 左右の padding を `calc(var(--btn-pad-x) * 0.4)` | 字を大きくしたぶん余白を詰めて**幅を元とほぼ同じに保つ** |
| `.pin-btn` | 大きさの指定を持たない | v2.8.7 の個別の 1.3倍は廃止（全体の 1.5倍に吸収） |
| `.skip-back-btn` / `.skip-forward-btn` | `font-size: var(--header-font)`（1.0倍） | 文字（`⏪10s`）なので 1.5倍にすると幅を食う |
| `.player-header` | `container-type: inline-size` | 幅は枠で決まるので見た目は変わらない |
| `@container (max-width: 500px)` | `.skip-sec { display: none }` | 狭い枠では秒数を隠し記号だけにする（秒数は title で読める） |

**しきい値 500px の根拠**（2026-10-02 Floorp 実測）: 秒数ありのボタン合計 381px ＋ 余白など 76px ＝ **457px** が収まる最小幅。余裕を見て 500px。
記号だけなら約 **403px** まで収まる（ヘッダー 421px で右端に 10px の余裕を実測）。

⚠️ **headless Chromium と Floorp で幅が違う。** 絵文字の字幅が Floorp の方が大きい（アイコン 36px 対 40px）。Chromium で収まっても Floorp ではみ出した（`/get-dev-workflow` 鉄則 #43）。

## 11. ローカル動画の拡大 ★v2.8.10

### 11-1. 🔴 動画だけを拡大し、枠で切る。操作バーは切らない

`<video class="custom-local-video">` は `.player-container`（`playerContainer_*`）の中に `position:absolute; 100%×100%` で置かれ、
**操作バー（`localOverlay_*`）は `.player-container` の外（枠の直下）にある。**
このため `<video>` だけを `transform: scale()` し、`.player-container` に `.zoomed`（`overflow:hidden`）を付ければ、**はみ出しは枠で切られ、操作バーは切れない。**

| 操作 | 実装 |
| :--- | :--- |
| 「標準 / 枠いっぱい」（`localZoomFit_*`） | `video.style.objectFit` = `contain` / `cover`。cover は枠の縦横比に合わせて上下か左右を切る |
| 「🔍 100〜300%」（`localZoom_*`、5%刻み） | `video.style.transform = scale(n)`（中心基準）。**ファイルに焼き込まれた黒帯**を消すためのもの（cover では消えない） |
| 表示値（`localZoomVal_*`）のダブルクリック | 標準・100% に戻す |

状態は `localZoom[cardId] = { fit, pct }`。`applyLocalZoom()` が描画と `.zoomed` の付け外しを行う。
**保存しない**（ローカル動画は再読み込みで消える）。**ファイルを替えたら標準へ戻す**（`handleLocalSelect()`）。
⚠️ 操作バーの HTML は2か所（新規の枠・セッション復元）で組み立てている。触るときは両方。

### 11-2. 対象外

🔴 **YouTube の枠は対象外**（利用者判断 2026-10-02）。動画と YouTube 自身の操作バーが**1つの iframe の中**にあり、動画だけを拡大できない（拡大すると字幕・画質の操作バーも切れる）。
⚠️ ヘッダーにボタンを置かなかったのは、9枠で右端の余裕が 10px しかないため（9節）。

### 11-3. 実測（2026-10-02 / Floorp / 1292×939）

4枠目（635×441）で 150% → video の幅 635 → 953px・中心のずれ ±2px 以内。目視で実際のローカル動画の黒帯が消え、操作バーは押せた。

## 12. 枠の境界線のドラッグ ★v2.8.11

### 12-1. 比の持ち方

列幅・行高を **`fr` の配列**で持ち、`grid-template-columns/rows` を `minmax(0, Nfr)` の並びで書く（`trackTemplate()`）。
比は **構成の署名**ごとに `gridRatios[署名] = { cols:[…], rows:[…] }` として `localStorage` の **`sync_grid_ratios`** へ保存する。

| 構成 | 署名 | 既定 |
| :--- | :--- | :--- |
| 3枠以上 | `列数x行数`（ピン中は末尾に `:pin`） | 均等 |
| 2枠・横並び | `n2:2x1` | 均等 |
| 2枠・縦並び / ピン | `n2:1x2` / `n2:1x2:pin` | 均等 / 行 `2:1` |
| 0〜1枠 | なし（つまみも出さない） | ─ |

- 🔴 **構成が変わったら、その構成で前に決めた比へ戻る（無ければ均等）。捨てない。** 別の構成の比を流用すると列数の違う配列を当てはめて崩れる。保存値の要素数が既定と違えば使わない。
- 🔴 **`order`・保存URL・`activeCardIds` には一切触れない**（大きさだけを変える ─ 5節）。
- 最小 80px（`GRID_MIN_TRACK_PX`）。動かすのは隣り合う2本だけで、合計は変わらない。
- 「全設定リセット」は `localStorage.clear()` なので比も消える。

### 12-2. つまみ

- `#gridSplitterLayer`（`#mainView` の子・`z-index:8`・`pointer-events:none`）に `.grid-splitter.v / .h` を隙間（gap 6px）の上へ置く。ふだんは透明で、ホバー・ドラッグ中だけ水色。
- 🔴 **ピン枠のように複数トラックにまたがる枠の上には出さない**（そこには隙間が無い）。区間ごとに枠の矩形と照らして切って出す。
- 🔴 **ドラッグ中は枠の iframe の `pointer-events` を切る**（iframe の上ではマウスの動きが親に届かない）。`.players-grid.resizing` でカードの transition も切る。
- 窓の大きさと一括コントローラーの出入り（`main-view` の padding が 0.3s で変わる）に `ResizeObserver` で追従する。

### 12-3. 均等に戻す

| 手段 | 実装 |
| :--- | :--- |
| つまみのダブルクリック | 🔴 **自前で判定する**（同じつまみへの2回目の mousedown が 450ms・4px 以内）。ネイティブの `dblclick` は「2回とも同じ要素」でしか発火せず、1回目の mouseup でつまみを作り直すと発火しなかった（2026-10-02 実機）。あわせて**動かしていなければ作り直さない** |
| 上部の **⊞**（`topGridResetBtn`・枠数 ➕ の右） | **今の構成に均等でない比が保存されているときだけ出す**（`updateGridResetBtn()`・差1%超）。押すとその構成だけ均等へ |

`resetGridRatios(署名)` が保存値を消して `updateLayout()` する。

### 12-4. debug_suite との取り決め

`setGridRatiosSuspended(true)` で保存した比を一時的に無視する（保存値は消さない）。**D-Y / D-Z は均等なトラックを前提に期待値を作るので、`runOne` がその間だけ止める。**

### 12-5. ローカル動画の履歴から選択画面を開く（同版）

履歴のローカル動画を押すと、`alert` の代わりにその枠の file input（`localFile_*`）を**クリックの処理の中で同期的に** `click()` する（`openLocalPicker()`）。間に `await` や `setTimeout` を挟むとブラウザが選択画面を開かない。ファイル名は履歴の `title`（ヒント）に出す。
🔴 **パスからファイルを開くことと、選択画面の初期フォルダの指定はブラウザが許さない。** Firefox 系には File System Access API も無く、アドオンからもできない（利用者へ説明済み 2026-10-02）。

## 13. 上部メニューの縮小と出し入れ ★v2.8.12

### 13-1. 縮小

- `.settings-toggle-btn` は padding `3px 8px`・文字 `0.78rem`。タイトルは `.topbar-title`。
- ラベルは `<span class="tb-label">` / `<span class="tb-long">` で包み、**1280px 以下で `.tb-long`、1000px 以下で `.tb-label` とタイトルを `display:none`**。`textContent` は変えない（debug_suite は id でボタンを探す）。正式名は `title`。
- 実測（headless・🐞 あり）: 1205px で右の空き 267px（縮小前 35px）。

### 13-2. 出し入れ

| 状態 | 実装 |
| :--- | :--- |
| 畳む（▲ `topbarCollapseBtn`） | `body.topbar-collapsed`。🔴 **バーを `position:absolute` にして流れから外し、`translateY(-100%)` で隠す。** グリッドは 35px 広がる |
| 出す | `body.topbar-peek`（`translateY(0)`）。🔴 **重ねるだけでレイアウトは動かさない**（出すたびに全枠の iframe が伸び縮みしないように） |
| 畳んでいる間 | 上端中央に `#topbarTab`（▼ メニュー / 出している間は バーの下で「▲ 隠す」）。▲ ボタンは 📌（固定に戻す） |
| 出し方（`#topbarTrigger`・`sync_topbar_trigger`） | **hover**: 上端 16px の帯、またはページの上辺から外へ抜けた `mouseout` で出す。**click**: タブでだけ出し入れ |
| 隠す（hover） | 🔴 **バーの `mouseleave` を起点に `TOPBAR_HIDE_MS`（0.6秒）。** メニュー（ドロップダウン・設定・マイリスト）が開いている間は隠さず、閉じるまで見張る |
| 保存 | `sync_topbar_collapsed` / `sync_topbar_trigger` |

### 13-3. 🔴 罠（実機で踏んだ順）

1. **閉じた設定パネル（`.settings-container`）は上へずらしているだけで、`translateY(-100%)` だと下端 35px が画面の上端に残る。** ふだんはトップバーの裏で見えないが、畳むと「残骸」になる。閉じたときは `translateY(calc(-100% - 45px))`、当たり判定も切る。
2. **速く上へ動かすと、上端の帯の中で `mousemove` が来ないままツールバーへ抜ける。** 上辺から外へ出た `mouseout`（`relatedTarget` なし）でも出す。
3. 🔴 **Firefox は iframe へ入るときも `relatedTarget` なしの `mouseout` を出す。** その位置が iframe なら無視する（さもないと上の方の動画に触れただけで出る）。
4. 🔴 **YouTube の枠（iframe）の上では親ページに `mousemove` が届かない。** 最後の位置で判定すると、バーから動画へ下ろしたときに隠れない。`mouseenter` / `mouseleave` で在否を持つ。
5. 隠すかの判定に `:hover` を使わない（合成イベントで変わらない）。

### 13-4. 設定欄

「メニューの出し方（上と下で別々に選べます）」の見出しの下に **⬆ 上部メニュー（畳んだとき）** と **⬇ 下部の一括コントローラー** を並べる。2026-10-02 に利用者が下部の欄を変えて「クリックのみでも開く」と報告した（画面キャプチャで確認）ため、見出しと矢印で分けた。

### 13-5. debug_suite との取り決め

`setTopbarSuspended(true)` で、畳んでいてもテストの間だけ出した状態にする（保存値は変えない）。`runOne` が **D-T 以外**の間だけ呼ぶ。
