## 4. スキルを増やす／分ける判断 ★2026-10-04 改訂（分割の規約を削除）

🔴 **行数を理由にした分割はしない**（2026-10-04 利用者と合意）。旧規約（目安 1,200行・分割専用セッション・分割の手順）は削除した。

| 理由 | 内容 |
| :--- | :--- |
| 前提が消えた | 目安と手順は claude.ai の制約（説明文の常時読み込み・設置事故が本数に比例・開発用と管理用のセッション分離）から作られた。Claude Code では仕様書はただのファイルで、セッションも1つ |
| 効果が小さい | 必要な節は grep や節ごとの読み出しで引ける。過去の分割でも「効いたのは必ず読まれる1本だけ・効果は僅か」と評価していた |
| 事故の種になる | 分割のたびに節番号の参照が宙に浮いた（2026-08-07 7件・08-15 2件・09-06 12件） |

- 大きいことで困るのは「探しにくさ」だけ。**節の見出しを保ち、終わった経緯は history へ退避する（5節）**ことで対処する。
- それでも節を別ファイルへ移すときは、🔴 **移す本文が指す節番号・スキル名を機械で列挙して1件ずつ確かめ、元の場所に1行の参照を残す**（上の事故の教訓）。
- 過去の分割の記録（`get-ui-spec` / `get-debug-suite` / `get-danmaku-spec` / `get-mgmt-guide` の分離）は各スキルの冒頭と git の履歴にある。

## 5. history への退避規約

**④で行う。** 置き場は `docs/history/`。

| ファイル | 対象 |
| :--- | :--- |
| `history_chat.md` | `/get-chat-feature-spec` から剪定した内容 |
| `history_protocol.md` | `/get-protocol-spec` から剪定した内容 |

### 退避するもの

- 実測データの詳細表（結論だけスキルに残す）
- 撤去した機能の実装記録
- 失効した罠・環境依存の記述
- 事前想定が覆った記録
- 検証に使った動画IDとその特性
- スキルから消したが、なぜそうなったかを追うのに要る経緯

### 退避しないもの（スキルに残す）

- 現行構成で有効な制約・罠
- 恒久的な行き止まり
- 確定した定数とその判定基準
- データ構造・メッセージ一覧

**スキル側には「詳細は history を参照」と一言だけ残す。**
