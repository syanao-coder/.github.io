## 2. 有効化

**`localStorage` の `sync_debug === '1'` が唯一の有効条件。** URLクエリはそのキーを操作する入口。

| 手段 | 動作 |
| :--- | :--- |
| `?debug=1` | `sync_debug` を `'1'` にして続行 |
| `?debug=0` | `sync_debug` と `sync_debug_resume` を**削除**し、何も作らずに `return` |
| クエリ無し | `sync_debug` の値だけで判定（**再読み込みをまたいで有効なまま**） |

🔴 **無効なら `DOMContentLoaded` を待たずに即 `return` する。** DOM・グローバル変数・
イベントリスナ・コンソール出力のいずれも作らない。全体が IIFE で `window` に何も生やさない。
実測（2026-08-04）: 無効時は `topDebugBtn` 等がすべて `null`、`TOP_MENUS.length = 3`、
`window.debugSuite = undefined`、コンソールに `[debug_suite]` の行が**0行**。

⚠️ **キー操作（Ctrl+Shift+D 等）での有効化は実装しない**（誤爆と実装コストに見合わない）。
⚠️ 「全設定・保存URLをリセット」は `localStorage.clear()` なので **`sync_debug` も消える。**

## 3. 構造（4ブロック）

```
ブロック1  有効化判定     … sync_debug の判定。無効ならここで return
ブロック2  共通ライブラリ … wait / sample / rect / overlap / hitTest / clickReal / expect / pc
ブロック3  UI生成         … CSS注入・トップバーのボタン・ドロップダウン・ログ・報告書コピー
ブロック4  テスト登録     … MENUS 定義・各テスト本体・TESTS 配列・実行制御・起動
```

起動は `DOMContentLoaded`（本体の `initApp()` より後に走る）。
UI は `.topmenu-anchor` + `.topmenu-dropdown` を**JSから動的生成**し、
**`/get-ui-spec` 1節の確定値に従う**。ボタンは `🐞 デバッグ`、位置はトップバーの**一番左**。
排他制御は **`TOP_MENUS.push({ panel:'debugMenu', btn:'topDebugBtn' })` の1行**で本体の仕組みに参加する
（本体側に分岐を足さない。`TOP_MENUS` が無ければ `console.warn` して単独動作）。

## 4. 共通ライブラリ（確定した引数と戻り値）

| 関数 | 引数 | 戻り値 |
| :--- | :--- | :--- |
| `await wait(ms)` | ミリ秒 | なし。**待ち時間を明示的に書かせるために用意する**（鉄則 #17 をコードで強制する） |
| 🔴 `await waitFor(fn, timeoutMs, intervalMs=100)` | 判定関数 / 上限 / 間隔 | `{ ok, value, waitedMs, tries }`。**値が届くまで待ってから基準値を取る** |
| 🔴 `await waitRectSettled(el, ms)` ★v1.6.2 | 要素 / 上限 | `{ settled, ms, rect }`。**矩形が2回続けて同じ値になるまでポーリング**（粒度50ms・既定2000ms） |
| `outsideOf(a, b)` / `inViewport(r)` ★v1.6.0 | 矩形 | `a` が `b` の外へ出ている量(px) / 画面内か |
| `hoverQ(el)` / `unhoverQ(el)` ★v1.6.0 | 要素 | `mouseover` / `mouseout` を**実際のイベント経路で**送る（関数の直呼びで代用しない） |
| `sample(fn, times, intervalMs)` | ─ | 配列。⚠️ **未使用。流し系のために残す。消さない** |
| 🔴 `hasAdvanced(startPos, cur, state)` | 基準位置 / 現在位置 / 状態 | `boolean` |
| `breakdownOf(list)` / `stateBreakdown(cardId)` | 状態の配列 / 枠ID | `"3×2 / 1×1（計3件）"` |
| `normalizeChoices(choices)` | 選択肢の配列 | 末尾に3件を足した配列 |
| `rect(el)` / `overlap(a, b)` | 要素 / 矩形2つ | 矩形 / 重なりの割合(%) |
| `await clickReal(el)` | 要素 | `{ blocked, reason, hit, rect }` ＋ `{ clicked }` |
| `expect(name, actual, expected)` | 名前 / 実測 / 期待 | `bool`。`expected` が関数なら述語、それ以外は文字列化して比較 |
| `pc(name, fn)` | 名前 / 判定関数 | `bool`。**positive control。** 1つでも落ちるとそのテストは判定不能 |
| 🔴 `note(name, value)` | 名前 / 値 | **合否を付けない観測を記録する** |
| `ask(name, choices)` | 名前 / 選択肢 | `Promise<{ name, choice, note }>` |

🔴 **`clickReal()` の `blocked` を無視しないこと。**
「関数は動くが実際には押せない」（`onclick` 属性・`pointer-events`・`z-index` の重なり）を
捕まえる唯一の仕掛けである。**関数の直呼びで代用しない。**

### 4-1. 🔴 `hasAdvanced()` ─ 絶対値で判定しない

判定は **`state === 1`（playing）かつ `現在位置 − 基準位置 >= 0.15秒`（`PLAY_ADVANCE_MIN`）**。
**基準位置は▶を押した直後に取る。**

⚠️ **v1.2.2 までは `位置 > 0.5` という絶対値だった。** 2026-08-09 の実測は **`0.4557`** で、
**この式では positive control（`D-P1`）が落ち、`D-P2`〜`D-P5` が全部「判定不能」になる。**
読み込み直後の自動再生の判定だけは基準が必ず 0 なので絶対値（`AUTOPLAY_POS_MIN` = 0.2）でよい。

### 4-2. 🔴 `note()` を `expect()` と分ける理由

**期待値を置けない観測値（状態遷移の内訳など）を `expect()` で足すと、
既存テストの判定数が変わり、版をまたいだ回帰比較ができなくなる。**
**観測は `note()`、合否は `expect()`。**

⭐ **実利が出た例**（2026-08-10 / 5-C）: 期待値を置けないので観測として出しただけの
**`responseContext.loggedOut` が、原因特定の決め手になった。**
**「期待値を置けない値」を捨てないこと。**

### 4-3. `waitFor()` の「まだ届いていない」の定義

`null` / `undefined` / `false` / 空文字 / 有限でない数値（`NaN`・`Infinity`）。
それ以外が返った時点で `ok: true`。時間切れなら `ok: false` と**最後に読んだ値**を返す。

### 4-4. `ask()` の選択肢

渡した選択肢の末尾に **「該当なし」「測れなかった（理由を自由記入へ）」「未実施」**を必ず足す（重複は作らない）。
🔴 **未選択のまま「確定」を押してもパネルは閉じない**（赤枠と警告を出す）。

## 5. 再読み込みをまたぐ記録

`LS_RESUME`（`sync_debug_resume`）を**2つの用途で使い回す。キーは増やさない。**

| `phase` | 用途 | 再読み込み後 |
| :--- | :--- | :--- |
| `after-reload` | `D-M7` の途中 | **自動で続きを実行する。** 🔴 `remaining` に**「すべて実行」の残りID**を載せる |
| `carry` | `D-P` の一括実行の区切り | **記録を復元するだけ。自動実行はしない**（有効期間30分） |

🔴 **退避するのは `report` 配列ごとにすること。** 実行中の1本だけを退避すると、
再読み込みで前のテストの判定記録が消え、コピー結果に最後の1本しか出ない（v1.0.0 で発生）。
⚠️ **版数（`DEBUG_SUITE_VERSION`）が違う退避データは破棄する。**

### 5-1. 🔴 「実行したつもりで実行していない」を作らない

**v1.0.0〜v1.4.0 には、`▶ すべて実行` が `D-M7` より後ろのテストを実行しないまま
「完了」と表示する不具合があった**（v1.4.1 で修正）。
原因は `D-M7` が `location.reload()` を呼ぶと `runAll` のループごと消えるのに、
再読み込み後の処理が「`D-M7` の続き」だけを実行して完了と表示していたこと。**`D-E1` が黙って飛ばされていた。**

🔴 **過去に `▶ すべて実行` で回帰確認をしたと記録している版があれば、
`D-M7` より後ろのテストは実測されていない可能性がある。**
**一括実行は、残りIDを持ち越し、全項目の実行を確認してから完了を出すこと**（鉄則 #29）。

⚠️ **`D-C10`（非ログイン）と `D-C11`（重い）は条件変更と時間が要るので毎回は回さない。**
**取得エンジンに手を入れた版でのみ実施する。**

⭐ **`D-X1` は「基盤が悪いのかテストが悪いのか」を最初に切り分けるためにある。** 基盤を改修したらまず走らせる。
🔴 **判定数は版をまたいだ回帰比較の基準である。** 改修後に**同じ判定数で通ること**を必ず確かめる
（2026-08-09 の改修では既存6本すべてが v1.2.2 と同一だった）。

### 7-1. `D-P` の一括実行

## 8. 🔴 実装上の決めごと

| 決めごと | 理由 |
| :--- | :--- |
| **人の準備が要るテストは `manual: true` を付け、`▶ すべて実行` から外す** | 取り違えた条件で測ると害になる（盾の切り替えが要る項目など） |
| 🔴 **条件は順序ではなく、測定コード自身に聞かせる** | v2.7.4 では各テストの開始時に盾の状態をダイアログで入力させ、必要な状態と違えば `[PC ❌]` にした（鉄則 #24 の実装形） |
| 🔴 **再読み込みをまたぐ positive control は `localStorage` に置く**（TTL・版数チェック付き） | メモリに置くと**盾の切り替え（再読み込みを伴う）で消える。** v2.7.4 で3項目が全部判定不能になった |
| 🔴 **固定時間で計測を打ち切らない。確定するまでポーリングする** | 鉄則 #27 |
| 🔴 **`clickReal()` は画面内にある要素へ `scrollIntoView` しない** | `body{overflow:hidden}` の画面では戻せなくなる（`/get-protocol-spec` 8節） |
| 🔴 **後始末で枠を空にしない。次のテストの冒頭で空にする** | 空にすると「一瞬映ってすぐ消えた」ように見え、**目視・スクリーンショットの時間が無くなる** |
| 🔴 **設置ガード** ★v1.5.2 | **一括実行の入口3つ（`runAll` / `runChatGroup` / `runPlaybackGroup`）すべてで、`APP_VERSION` が `EXPECT_APP_VERSION` と一致するか・版数バッジが warn/ng でないかを確かめ、揃っていなければ実行せず中止する。** 報告書の冒頭に版数バッジの実測を必ず出す。⚠️ **2026-08-15、版数が混在した状態で5〜6分の測定を丸ごと無駄にした。** 🔴 **「設置が正しいこと」を人の目視に委ねてはいけない**（鉄則 #34） |
| 🔴 **前提条件は `expect` ではなく `pc` で書く** | 2026-08-15、`D-L6` の「設定が `close` になっている」を `expect` に置いたため、**機能は正常なのに「不合格1本」として集計された。** 前提を `expect` に置くと**条件の不備が機能の欠陥に見える。** あわせて**押した時点で前提を確かめ、成立しなければ待たせる前に中止する** |
| 🔴 **矩形を測る判定は、遷移が収束してから測る** ★v1.6.2 | `.settings-container`（📂 / ▼）は**押し下げ式で `transform 0.3s`** かけて滑る。`clickReal()` の `SETTLE_MS = 60ms` では足りず、**滑っている途中の矩形**（上へ122px / 162px）を掴んで偽の不合格を出した。**`waitRectSettled()` を使い、収束しなければ PC を落として「測れていない」と分かるようにする。** ⭐ 収束時間 ─ `.topmenu-dropdown` **101〜102ms** / `.settings-container` **357〜361ms** |
| 🔴 **要素の挿入位置をクラス名で決めない** ★v1.6.1 | `buildUI()` が `querySelector('.topmenu-anchor')`（DOM順で最初）から挿入位置を決めていたため、**v2.8.2 で版数バッジを同じクラスで包んだ瞬間に 🐞 がトップバー左端へ移動し、`right: 0` の420pxパネルが画面の左外へ95pxはみ出して押せなくなった。** **ボタンのIDから `closest('.topmenu-anchor')` で引くこと** |
| ⚠️ **本体の `const` は `window` から読めない** | `APP_VERSION` / `APP_HISTORY` / `HELP_TEXTS` / `TOP_MENUS` はグローバル**レキシカル**環境に入る。**名前で直接参照し、TDZ 対策で `try/catch`。** `window.X` は `undefined` |
| 🔴 **トグルや非同期な状態を、操作した直後に読まない** | 2026-08-15、🌊 を押した直後に `flowLive` を読み、**tick が1度も回る前の初期値**を拾って「測れていないのに⚪」になった。**反映のための間隔を置き、2点で読む。** ⚠️ **「見た目が正しい」ことと「意図した経路を通っている」ことは別。後者を判定に入れる** |
| 🔴 **本体の版数を期待値に持つテストは、定数1か所にまとめる** | `EXPECT_APP_VERSION`。2026-08-15、`D-V1` の期待値が `2.7.4` のまま残り、**正しい `2.7.5` を不合格と報告した** |
| 🔴 **押し下げ式ヘッダーのボタンに被覆チェックは適用できない** | `.player-header{height:0;overflow:hidden}` ＋ `.player-card:hover` で高さが出る作りのため、マウスが枠外にあると `elementFromPoint` は `div.player-card` を返す。**CSS の `:hover` は合成イベントでは作れない。** 判定は「クリックが発火したか」「状態が変わったか」で行う。⚠️ **トップバー・枠内通知の閉じるボタンは常時表示なので従来どおり被覆で判定してよい** |
| 🔴 **トグルを押すテストは、押す前の状態を必ず読む** | 前の実行がオンのまま終わっていると、押した結果オフになる（`D-C4` で実際に0件になった）。**後始末でオフへ戻すこと** |
| 認証情報の走査（`scanSecrets`） | 規則は `SAPISIDHASH` / `APISID` / 16進40桁 / `<unix秒>_<16進40桁>`。⚠️ **16進40桁に `\b` は使えない**（`_` は語構成文字で境界にならず positive control が落ちる）。⚠️ **検査対象からデバッグパネル自身を除くこと**（検出パターン名がパネルに出るため必ず誤検出する） |
| 一括実行中に押されたら知らせる | `window.alert`。**ログだけでは気づけない** |
| 🔴 `?debug=0` で削除するキーは**4本** | `sync_debug` / `sync_debug_resume` / `sync_debug_playback_pc` / **`sync_debug_meta`**（ラベル・実施メモ / TTL 12時間） |
| ラベル・実施メモも `localStorage` へ | 盾の切り替えが再読み込みを伴うためメモリに置けない。**`D-X2` が自動で設定するので人の入力は不要** |

### 9-3. 🔴 用紙が機械で行う3つの照合 ★v3.0.0

### 9-4. 項目定義の書式（`STEPS`）

🔴 **骨組み（CSS・描画・自己診断・コピー・下書き保存・3つの照合）は毎回そのまま。**
**`FORM_META` と `STEPS` だけを差し替える。**

`STEPS` は上から順に描画する配列で、要素は3種類ある。

| 種類 | キー | 用途 |
| :--- | :--- | :--- |
| 節見出し | `sec` / `html` | 節の区切りと、その節の説明 |
| 手順 | `ttl` / `rows` / `note` / `copy` / `ans` | 1つのテスト。**`rows` は `[やること, これで何をしたいか]` の2列** |
| 回答のみ | `ans` だけ | 手順を伴わない設問（時間帯の選択など） |

`ans` のキー:

| キー | 内容 |
| :--- | :--- |
| `id` | 🔴 **手順の見出し番号と同じにする**（`T1` の手順 → `T1` の欄） |
| `type` | `suite`（基盤の出力を貼る）/ `paste` / `radio` / `check` / `text` |
| `expectIds` | 🔴 `type: 'suite'` のとき、**その欄に揃っているべきテストIDの配列**（9-3節の照合1） |
| `options` | **「未実施」「測れなかった（理由は自由記入へ）」は自動で足される** |
| `secret` | `true` で**「ある / ない」の radio に強制** |
| `optional` | `true` で未記入として数えない |

🔴 **`copy` は配列にしない。** 1項目1ボタン（9-2節 鉄則3）を型で強制する。

`FORM_META` は `defVersion`（回ごとに上げる）/ `work`（対象の作業名）/ `base`（基点コード）/
`expectApp`（期待する `APP_VERSION`）/ `expectSuite`（期待する `debug_suite` の版数）/ `note`（冒頭の注意）。

### 9-5. 自己診断

**「報告書用にコピー」を押した瞬間に走り、出力の1節目へ表が入る。利用者は何も操作しない。**
検査するもの: 項目数 / 種別ごとの描画 / **画像要素が無いこと** / `secret` の強制 / 選択肢の自動追加 /
1万文字を入れたときの欄の高さ / 未記入と赤枠の一致 / 下書きの往復 / 出力の並び順 / 「（未記入）」の表記 /
**3つの照合の結果**。

🔴 **自分自身を参照しないよう、テスト結果の本文を先に組み立ててから、その文字列を検査する。**
🔴 **照合そのものにも positive control を置く。** 偽のIDを与えたときに「欠けている」と出ること、
偽の版数を与えたときに落ちることを、自己診断の中で確かめる
（`/get-dev-workflow` 鉄則 #22 ─ 判定手段を新設したら反応する条件を1つ用意する）。

### 9-6. 🔴 実装上の罠

- **貼り付け欄の高さは CSS で固定する**（`height` と `max-height` の両方 / `resize: none`）。
  実測: **25,989文字を貼っても 180px のまま・横スクロールも出ない**
- 🔴 **囲みのバッククォートは本文中の最長より1つ長くする。**
  `debug_suite` の出力はコードフェンスを含むため、**3連では壊れる**
- 未記入は**赤枠＋ヘッダに件数**を出し、出力時に警告する。出力Markdownには **`（未記入）`** と明記する
- **クリップボードが失敗したときの退路として `.md` のダウンロードを置く**
- 🔴 **テストIDの抽出は、出力の一覧表の行頭から取る。** ログの文言から拾わない
